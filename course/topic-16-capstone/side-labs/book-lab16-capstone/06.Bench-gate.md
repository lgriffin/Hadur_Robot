# Bench gate

Nothing merges on a hunch. Decide before you run what the bench has to show, then run it, then let the interval decide.

## Write the gate first

In `docs/bench/<your-feature>.md`, before any run, write:

- **Opponents.** The ones the feature is meant to help, and a regression set it must not hurt. For a rammer escape: `sample.RamFire` and the other sample bots. For a mirror detector: your sparring mirror robot and the sample bots. For a posture gate: the duel opponents you already bench.
- **Metric.** Score share, as in lab 12.
- **Conditions.** Cold, 35 rounds, at least 10 seeds, same machine, nothing else running. Hadur found that 5 seeds can disagree with themselves by 2 points (the M6 jar gave 51.3 and 53.7), and that single opponents move 3 to 14 points between runs of 5 by 35 (L-19).
- **Gain.** What you expect on the target opponents, and how big a difference you would call worth shipping.
- **Regression.** What counts as hurt. A simple rule: the paired difference on any regression opponent has an interval that lies wholly below 0.

## Run a paired A/B

Use the bench from lab 12 (it is in your `lab-16/hadurling-bench`). Baseline is lab 13 (the jar before your feature). Candidate is lab 16. Both fight the same opponent on the same seeds, and the report is the mean of the per-seed differences with its 95% interval. Use a JDK from 17 to 21.

```text
difference per seed = candidate share - baseline share
```

Pairing cancels what the seed did to both robots: a lucky opening, a hard field. Whatever remains is your change.

Build both jars, then run the bench from `lab-16/hadurling-bench`:

```sh
(cd course-labs/lab-13 && mvn -B package -DskipTests)
(cd course-labs/lab-16 && mvn -B package -DskipTests)
cd course-labs/lab-16/hadurling-bench
mvn -B -q exec:java -Dexec.args="--opponent sample.RamFire --rounds 35 --seeds 10 \
  --baseline-jar ../../lab-13/hadurling-robot/target/hadurling.Hadurling_0.1.jar \
  --baseline-name lab-13 --candidate-name lab-16 --report ../docs/bench/my-feature.md"
```

The jars of both labs are called `hadurling.Hadurling` version 0.1. The bench installs each in a Robocode home of its own, so they do not collide. Cold is the default, which is what you want: each battle starts with no saved profile. Add `--opponent-jar` for a sparring robot of your own. If you change the robot's version, pass `--robot-jar` and `--robot` too, because the bench looks for `hadurling.Hadurling 0.1` by default.

The bench exits with the report on screen and in the `--report` file. A battle that fails stops the run with a message and never counts as a score of 0.

Run the target set, then the regression set. Keep the raw output (the engine logs are in `work/<time>`).

## Read the interval

| What you see | Verdict | What to do |
|---|---|---|
| Target difference interval wholly above 0, regression set unhurt | **Gain** | ship it |
| Target interval spans 0, regression unhurt, code is simpler or neutral | **No measurable change** | ship only if it is simpler; say "neutral" in the notes |
| Target interval spans 0 and the code is more complex | **No measurable change** | do not ship; keep the branch |
| Any regression opponent interval wholly below 0 | **Harm** | do not ship; tighten the trigger and run again |

Hadur's examples of each:

- **Gain:** RAM-2 and MIR-1 raised the weak-bot set from 74.8% to 86.8% mean share and cut rounds lost from 203 to 69 (`docs/bench/r9-weak-leak.md`).
- **Neutral and simpler:** in M6, dropping the posture's fire holds raised bullet damage about 15% at the same APS. Release 3.0 kept it because the rule was simpler (`docs/bench/m6-gates.md`).
- **Harm, then a fix:** RAM-2's first cut lifted the weak set to 87.9% but cost up to 15 points against strong robots. A confirmation rule brought the top 19 back to unchanged (48.6% to 48.8%) at the price of 1.1 points on the weak set.
- **Not met, said so:** S6's gate needed zero skipped turns and got 72. The report said so and named the next thing to try.

## Things that go wrong

- **Choosing the opponents after seeing the result.** Do not.
- **Stopping when it looks good.** Fix the number of seeds in the gate and run all of them.
- **Running `mvn` during the bench.** It inflates skipped turns (L-19).
- **Reading one opponent's swing as a finding.** Under about 8 points per opponent is noise at 5 seeds.
- **Forgetting the baseline's own noise.** Run the baseline against itself once (the same jar as `--robot-jar` and `--baseline-jar`). The interval of that difference is how big "nothing" looks on your machine.

## Write the verdict

At the end of the bench report, write: the table, the conditions, the verdict in one of the four forms above, and what you would try next. If the verdict is Harm, you have still done the work. A stage that shows its change does not help is a result. Hadur's ledger keeps those too (`data/learnings.md`, for example L-13: memory has not paid off against Shadow).

## Check yourself

- Was the gate written before the first run?
- Did the regression set get the same number of seeds as the target set?
- Could someone else reproduce your table from your report alone?
