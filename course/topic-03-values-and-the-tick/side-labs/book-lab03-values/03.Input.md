# Input: an immutable snapshot

`Input` is everything the brain may know at the start of a tick: our own state and the events
since the last tick. Create `src/main/java/hadurling/model/Input.java`.

```java
public final class Input {

    private final long time;
    private final double x;
    private final double y;
    private final double heading;
    private final double velocity;
    private final double energy;
    private final double gunHeat;
    private final double gunHeading;
    private final double radarHeading;
    private final List<Event> events;

    /**
     * A snapshot of one tick.
     *
     * @param time the tick number
     * @param x our x in px
     * @param y our y in px
     * @param heading our body's heading in radians
     * @param velocity our velocity in px/tick
     * @param energy our energy
     * @param gunHeat the gun's heat; it can fire at 0
     * @param gunHeading the gun's heading in radians
     * @param radarHeading the radar's heading in radians
     * @param events what happened since the last tick, in order; copied, so the caller may
     *     go on changing its own list
     */
    public Input(long time, double x, double y, double heading, double velocity, double energy,
            double gunHeat, double gunHeading, double radarHeading, List<Event> events) {
        this.time = time;
        this.x = x;
        this.y = y;
        this.heading = heading;
        this.velocity = velocity;
        this.energy = energy;
        this.gunHeat = gunHeat;
        this.gunHeading = gunHeading;
        this.radarHeading = radarHeading;
        // List.copyOf is a defensive copy and is also unmodifiable (and rejects nulls).
        this.events = List.copyOf(events);
    }
```

## The important line

```java
this.events = List.copyOf(events);
```

`List.copyOf` (Java 10) makes a new list with the same elements. That list is
**unmodifiable**: calling `add` throws. And it is a **copy**, so if the caller goes on changing
its own list, our `Input` does not see it. This is a **defensive copy**. Without it, the
`final` keyword on `events` would be a lie: the *reference* is final, but the list it points to
could change under us.

In the robot, the adapter keeps one `pending` list, builds an `Input` from it, and then
clears `pending` for the next tick. With a defensive copy that is safe. Without one, clearing it
would empty the `Input` we just built.

## Getters, equals, hashCode

Add one getter per field (`time()`, `x()`, and so on), then `equals`, `hashCode` and
`toString`. For `equals`, compare each `double` with `Event.same(...)` and the list with
`events.equals(...)`; for `hashCode` use `Objects.hash(...)`.

```java
    @Override
    public boolean equals(Object o) {
        if (!(o instanceof Input)) return false;
        Input i = (Input) o;
        return time == i.time && Event.same(x, i.x) && Event.same(y, i.y)
            && Event.same(heading, i.heading) && Event.same(velocity, i.velocity)
            && Event.same(energy, i.energy) && Event.same(gunHeat, i.gunHeat)
            && Event.same(gunHeading, i.gunHeading) && Event.same(radarHeading, i.radarHeading)
            && events.equals(i.events);
    }
```

`same` is package-private (no `public`), so only classes in `hadurling.model` can use it. That is
the right amount of sharing.

## Units

Say them in Javadoc, every time: angles in radians, 0 north, clockwise; positions in px; time in
ticks. A wrong unit is the most common bug in robot code and the type system will not catch it,
since all of them are `double`.
