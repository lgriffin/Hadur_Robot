# Lab 03: Values and the tick

At the end of Lab 02, Hadurling's decisions still sit inside engine event handlers, mixed up with
engine calls. In this lab you pull them out. Everything the robot knows at the start of a tick
becomes one immutable value, `Input`. Everything it wants to do becomes another, `Orders`. A
small class, `Brain`, turns one into the other. The robot class shrinks to a translator.

## Objectives

By the end of this lab you can:

- write an immutable class: `final` fields, no setters, a constructor that copies what it is given
- model a closed set of alternatives with an abstract class and a private constructor
- implement `equals`, `hashCode` and `toString` by hand, and say why NaN needs care
- use a builder and a named constant to make a value class pleasant to use
- test a decision-maker with no engine at all
- describe a tick as: events in, input built, orders out, orders applied

## What you start from

`course-labs/lab-02`, or this lab's [`start.zip`](./archives/start.zip).

## What you will have at the end

- a package `hadurling.model` with `Input`, `Event` (and five event types) and `Orders`
- `Brain`, with all of Hadurling's decisions, and no `import robocode`
- `Hadurling` as a thin adapter: handlers queue events; each tick builds an `Input`, asks the
  `Brain`, applies the `Orders`
- `ModelTest` and `BrainTest`, which run in milliseconds

This is `course-labs/lab-03`.
