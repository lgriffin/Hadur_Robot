# Event: a closed hierarchy

During a tick several things may happen: we see an enemy, we hit a wall, a bullet hits someone.
Each is an **event**. They have different data, but we want to put them in one list, in order.

## An abstract base class, a private constructor

```java
public abstract class Event {

    private Event() {}
```

- `abstract` means you cannot write `new Event()`; it exists only to be extended.
- The constructor is **private**. Only code inside the `Event` class itself can call it, and the
  subclasses we write are *nested inside* `Event`, so they can. Nobody else can ever add a
  subclass. That makes the set of events **closed**: if you handle five types, you have handled
  them all. (Java 17 spells this `sealed`; the effect is the same.)

## One event

Add the nested class for hitting a wall, inside `Event`:

```java
    /** We drove into a wall. */
    public static final class HitWall extends Event {
        private final double bearing;

        /**
         * A wall hit.
         *
         * @param bearing the angle to the wall relative to our heading, in radians
         */
        public HitWall(double bearing) {
            this.bearing = bearing;
        }

        /** @return the angle to the wall relative to our heading, in radians */
        public double bearing() { return bearing; }

        @Override
        public boolean equals(Object o) {
            return o instanceof HitWall && same(bearing, ((HitWall) o).bearing);
        }

        @Override
        public int hashCode() { return Double.hashCode(bearing); }

        @Override
        public String toString() { return "HitWall[bearing=" + bearing + "]"; }
    }
```

Study the parts, because the other four events repeat them.

- `public static final class HitWall extends Event`: a nested class. `static` here means it does
  not need an outer `Event` object. `final` stops further subclasses.
- `private final double bearing`: set once, in the constructor, never again.
- `bearing()` is a **getter**. We name it `bearing()`, not `getBearing()`, as records do.
- `equals` says when two events are the same. It checks the type (`instanceof`) and then the
  fields. `hashCode` must agree with it: equal objects must have equal hash codes, or they will
  misbehave in a `HashSet`. `Double.hashCode` does it for one field.
- `toString` makes failure messages readable. `HitWall[bearing=0.1]` beats `HitWall@1f2e3d`.

## Comparing doubles

`equals` for the `double` field calls a helper:

```java
    static boolean same(double a, double b) {
        return Double.compare(a, b) == 0;
    }
```

Why not `a == b`? Because in Java `Double.NaN == Double.NaN` is **false**. A `NaN` ("not a
number") appears when a number is missing. If a value holding NaN could never equal itself,
tests on values with NaN would fail for no good reason. `Double.compare` treats NaN as equal to
NaN. (It also tells `0.0` from `-0.0`, which is what we want when comparing exactly.)

## The other four

Write `Scan`, `HitByBullet`, `BulletHit` and `RobotDeath` the same way. Their fields:

| Event | Fields |
|---|---|
| `Scan` | `name`, `bearing`, `distance`, `energy`, `heading`, `velocity` |
| `HitByBullet` | `shooter`, `power` |
| `BulletHit` | `victim`, `power` |
| `RobotDeath` | `name` |

For the `String` fields, use `Objects.requireNonNull(name)` in the constructor: it throws at
once if someone passes `null`, rather than failing mysteriously later. Compare strings with
`.equals`, never `==`. The complete file is `course-labs/lab-03/src/main/java/hadurling/model/Event.java`
if you want to check.
