# Exercises

## 1. Another event

Add an event `SkippedTurn` carrying the tick that was skipped (a `long`). Write it in the same
style as the others, add `onSkippedTurn` to the robot to queue it, and have the brain set a
boolean `rushed` that it can use later. Write a `ModelTest` case that two `SkippedTurn(5)` are equal and
that `SkippedTurn(5)` and `SkippedTurn(6)` are not.

## 2. Break immutability, then repair it

Temporarily change `Input` to store `events` without copying. Which test fails? Now keep the copy
but remove `final` from one field and add a setter. Which tests would catch that? (None of ours:
tests of immutability are hard to write, which is why the language feature `final` helps.) Put
everything back.

## 3. A smarter brain

Change the `Brain` to fire power 3 when the enemy's energy is below 20, since a hit then kills it
or nearly does (`scan.energy()`). Write the test first: build a `Scan` with energy 10, and
assert `firePower() == 3`. Watch it fail, then write the code.

## 4. Orders you can read

Add `Orders.toString` output that leaves out NaN fields, so `Orders[ahead=100.0, fire=1.0]` is
printed for an order that sets only those two. Which is easier to read in a failing test?
