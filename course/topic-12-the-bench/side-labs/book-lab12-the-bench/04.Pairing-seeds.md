# Pairing seeds: A/B

You change the gun and want to know whether Hadurling got better. The tempting method: fight the
old one five times, fight the new one five times, compare the averages. It works badly, and here is
why.

Some seeds are easy and some are hard, for **both** versions. Seed 3 might start Hadurling in a
corner next to a rammer. If the old version fights seeds 1 to 5 and the new one fights seeds 6 to 10,
the difference between them includes the difference between the seeds. That noise can be bigger than
the effect you are looking for.

**Pair them.** Fight both on seeds 1 to 5. Then for each seed take the *difference*
(candidate minus baseline). The seed's difficulty is in both numbers, so it cancels. What is left is
the effect of the change, plus a smaller noise.

## `pairedDiff`

```java
public static Stats pairedDiff(List<Double> candidate, List<Double> baseline) {
    int n = Math.min(candidate.size(), baseline.size());
    List<Double> diffs = new ArrayList<>();
    for (int i = 0; i < n; i++) diffs.add(candidate.get(i) - baseline.get(i));
    return of(diffs);
}
```

Position `i` in both lists must be the same seed. That is a promise the bench keeps by always
fighting seeds 1 to N in order.

The paired differences are one more list, so `of` gives their mean and interval. The new part is the
verdict.

## The verdict

```java
public Verdict verdict() {
    if (Double.isNaN(halfWidth)) return Verdict.UNCLEAR;
    if (low() > 0) return Verdict.BETTER;
    if (high() < 0) return Verdict.WORSE;
    return Verdict.UNCLEAR;
}
```

That is requirement `HL-35`. Better means the **lowest** end of the interval is above zero. Worse
means the **highest** end is below zero. Anything else, including "we do not know how wide the
interval is", is unclear. `UNCLEAR` is the default answer. A bench that says "better" on weak
evidence is worse than no bench.

## Prove that pairing helps

This test builds the situation in the story above:

```java
@Test
@Tag("HL-35")
@DisplayName("a paired difference cancels what both versions share")
void pairingCancelsTheSeedEffect() {
    // The seeds swing both versions by 20 points, but the candidate is always 3 ahead.
    List<Double> baseline = List.of(0.40, 0.60, 0.50, 0.30, 0.55);
    List<Double> candidate = List.of(0.43, 0.63, 0.53, 0.33, 0.58);
    Stats diff = Stats.pairedDiff(candidate, baseline);
    assertEquals(0.03, diff.mean(), 1e-12);
    assertEquals(0.0, diff.halfWidth(), 1e-9);
    assertEquals(Stats.Verdict.BETTER, diff.verdict());
    // Compared as two separate samples, the same data cannot tell them apart.
    Stats a = Stats.of(baseline);
    Stats b = Stats.of(candidate);
    assertTrue(b.low() < a.high() && a.low() < b.high(), "the intervals of the two means overlap");
}
```

The candidate is always exactly 3 points ahead, a perfectly clear improvement. Compared as two
averages, the intervals overlap and you could not tell. Compared as pairs, there is no doubt.

Another test pins the verdicts down: a spread of consistent small gains is `BETTER`, a spread of
consistent losses is `WORSE`, mixed results are `UNCLEAR`, and one sample is `UNCLEAR`.

## Report

`Report` turns lists of shares into Markdown a human can read, using `Stats` for every number.
`Report.single` prints a table with one row per opponent and an overall row. `Report.compare`
prints the two versions, the paired difference in points and one sentence:

```java
case BETTER:
    b.append("**Better, outside the noise:** the whole interval is above zero.\n");
    break;
...
default:
    b.append("**Inside the noise:** the interval includes zero (or there are too few seeds to say). "
        + "Run more seeds before believing either way.\n");
```

The default says what to do next. `ReportTest` checks the three outcomes and that the single report
lists each opponent. Because `Report` is plain strings, none of it needs a battle.
