# Write the requirements

| ID | Pattern | Requirement |
|----|---------|-------------|
| HL-33 | Ubiquitous | The bench shall report a score share as a mean with a 95% confidence interval over seeds, using Student's t. |
| HL-34 | Unwanted behaviour | If fewer than two seeds were fought, then the bench shall report the interval as unknown and not as zero. |
| HL-35 | Event-driven | When two versions are compared, the bench shall pair their results by seed and call the change better or worse only if the whole interval of the paired differences lies on one side of zero. |

All three are about the **report**, not about the robot. A requirement can be about any part of the
project: this is the first time one is about a tool.

`HL-34` is the same kind of rule as `HL-25` in lab 11: *unknown is not zero*. A report that says
"+/- 0.0" for one battle claims perfect certainty from no evidence. It must say "?".

`HL-35` is the one to read twice. "Only if the **whole** interval lies on one side of zero." A
difference of +2 points with an interval of +/- 10 is not better; it is inside the noise.

Add a new line to `RequirementsTraceabilityTest` so that it also scans the bench module:

```java
for (String module : List.of("hadurling-core", "hadurling-robot", "hadurling-bench")) {
```

Without this the tags in the bench tests would not count, and `HL-33` would look untested.
