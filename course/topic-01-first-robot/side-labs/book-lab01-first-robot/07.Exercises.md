# Exercises

Each one changes only `Hadurling.java`. Run the battle after each to see the effect.

## 1. Fire harder when closer

Right now every bullet is power 1. A harder bullet does more damage but travels more slowly, so
it is easier to dodge, and it costs more energy. Close up, the extra damage is worth it.

Choose the power from the distance: `e.getDistance()` is in pixels. For example, power 3 under
150 pixels, power 2 under 400, power 1 beyond. Replace the `FIRE_POWER` constant with a small
method:

```java
private double firePowerFor(double distance) {
    // your rule here
}
```

A method is a named chunk of code that returns a value. Notice it makes the rule easy to read
and change in one place. Which distances give the best result against `sample.Walls`?

## 2. Count your hits

Override `onBulletHit(BulletHitEvent e)` and add a second static field `hits`. Print the totals
at the end of each round by overriding `onRoundEnded(RoundEndedEvent e)`. Which of `hits` and
`roundsStarted` needs to be static, and why? (Both: they must survive the new object each
round.)

## 3. Reverse on a timer

A predictable robot is a target. In the main loop, flip `direction` every 40 ticks
(`getTime() % 40 == 0`). Does it survive longer against `sample.Tracker`? What is the cost of
reversing too often? (A robot that reverses every tick barely moves.)

## Think about it

Everything in `onScannedRobot` runs only when the radar sees the enemy. What does the robot do
on a tick with no scan? Which orders does it keep from the last tick? Write the answer down
before Lab 03, where we make this idea explicit.
