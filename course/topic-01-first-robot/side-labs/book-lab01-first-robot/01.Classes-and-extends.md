# Classes, extends and override

Open `src/main/java/hadurling/Hadurling.java`. It is short:

```java
package hadurling;

import robocode.AdvancedRobot;

public class Hadurling extends AdvancedRobot {

    @Override
    public void run() {
        while (true) {
            setTurnRadarRight(360);
            execute();
        }
    }
}
```

Read it line by line. Every part is a Java idea you will use for the rest of the course.

## A class is a blueprint

`public class Hadurling` declares a **class**: a blueprint for a kind of thing. Robocode will
build one **object** from this blueprint for each round of a battle (that is called
*instantiating* the class, and it is the engine that does it, not you). The class holds what
the robot *knows* (its **fields**) and what it *can do* (its **methods**).

`package hadurling;` says which folder of the source tree the class lives in. Robocode finds
your robot by its full name, `hadurling.Hadurling`, which is why the properties file in
`src/main/resources/hadurling/` says `robot.classname=hadurling.Hadurling`.

## `extends`: borrowing a ready-made robot

`extends AdvancedRobot` means *Hadurling is an AdvancedRobot, plus whatever we add*. Robocode
ships the class `AdvancedRobot`. It already knows how to turn, drive, fire, read its own
position and talk to the engine. By extending it, Hadurling inherits all of that for free.

You will see the word **inherit** a lot. If `AdvancedRobot` has a method `getX()`, then
`Hadurling` has it too, and you can call it as if you had written it.

## `@Override`: replacing a method

`AdvancedRobot` has a method called `run()` that does nothing. The engine calls `run()` once
per round, on the robot's own thread, and expects you to keep the robot busy from there. When
you write a method with the same name and the same parameters in your own class, you
**override** it: the engine's call now lands in your version.

`@Override` is an **annotation**. It tells the compiler "I mean to replace a method I
inherited". If you misspell the name (`runn()`), the compiler stops you, instead of quietly
creating a new method nobody calls. Always write it.

## The loop and `execute()`

Robocode runs in **ticks** (also called turns): about 30 a second. In one tick the engine
moves every bullet and robot one step, then asks each robot what it wants to do.

`setTurnRadarRight(360)` does **not** turn the radar. Methods that start with `set` only
*queue an order*. The orders take effect when you call `execute()`, which ends your turn and
waits for the next tick. That is why the code is a `while (true)` loop: queue orders, execute,
repeat, until the round is over and the engine stops the thread.

Angles passed to `setTurnRadarRight` are in **degrees**. Soon we will switch to the `...Radians`
versions, because trigonometry (`Math.sin`, `Math.atan2`) works in radians.

## Try it

Change `360` to `90` and rebuild with `mvn -B verify`. Can you predict what happens in
Robocode? (The radar turns 90 degrees, then each tick queues another 90, so it keeps turning,
but slower than before. Radar speed is capped at 45 degrees per tick anyway, so you may not
see a difference. Try `10` and you will.) Put it back to `360` before you move on.
