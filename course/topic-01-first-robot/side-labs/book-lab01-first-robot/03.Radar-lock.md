# Radar lock

The radar is a narrow beam that sweeps as it turns. When it passes over an enemy robot, the
engine calls the method `onScannedRobot` with a report on what it saw. Spinning the radar is
how you find the enemy. **Locking** the radar means pointing it at the enemy each tick so you
never lose track.

## Events

The engine tells your robot about things that happen by calling methods you override. These
are **event handlers**. This one fires when the radar sees a robot:

```java
@Override
public void onScannedRobot(ScannedRobotEvent e) {
    // e describes what the radar saw
}
```

Add `import robocode.ScannedRobotEvent;` at the top. The parameter `e` is an object of the
class `ScannedRobotEvent`. Useful questions to ask it:

| Call | Meaning |
|---|---|
| `e.getBearingRadians()` | the enemy's direction **relative to our heading** |
| `e.getDistance()` | how far away it is, in pixels |
| `e.getName()` | its name |

Handlers run during `execute()`. So the radar reports arrive while your `run()` loop is
waiting.

## Angles

Robocode measures angles in **radians** (a full circle is 2 pi, about 6.28). 0 is north, and
angles grow **clockwise**, so east is pi / 2. There are two kinds of angle to keep apart:

- **absolute**: a compass direction, such as the enemy's direction on the map
- **relative**: how far to turn from where you are pointing now

`getBearingRadians()` is relative. To get the absolute direction of the enemy, add our own
heading:

```java
double enemyDirection = getHeadingRadians() + e.getBearingRadians();
```

To turn the radar to it, we need a relative angle again: the enemy's direction minus where the
radar points now. The result might be 350 degrees, but the short way round is 10 degrees the
other way. Robocode's helper `Utils.normalRelativeAngle` folds any angle into the range minus
pi to pi, which is the short way. Add `import robocode.util.Utils;` and write:

```java
double radarTurn = Utils.normalRelativeAngle(enemyDirection - getRadarHeadingRadians());
setTurnRadarRightRadians(2 * radarTurn);
```

Why `2 *`? If we turned exactly to the enemy, the radar would stop on it, and a beam that
does not move only sees a thin line: the enemy might drift out of it by the next tick. Turning
**twice as far** makes the radar overshoot, sweep back across the enemy, and see it again every
tick. It is a classic trick.

## Lose and find again

Sometimes the enemy slips out of the beam. We want to notice, and start sweeping again. Add
one more field to remember when the last scan was:

```java
/** The tick on which the radar last saw the enemy. */
private long lastScanTime = -100;
```

`long` is a big whole number, the type `getTime()` returns. Start the handler by recording the
time:

```java
lastScanTime = getTime();
```

Then in the main loop, before `execute()`:

```java
if (getTime() - lastScanTime > 2) {
    setTurnRadarRightRadians(Double.POSITIVE_INFINITY);
}
```

If more than two ticks have passed with no scan, order the radar to turn forever (infinity)
until it finds something. As soon as `onScannedRobot` fires, it replaces that order with the
lock.

Finally, in `run()`, make the gun and radar independent of the body, or the whole aim swings
every time the body turns:

```java
setAdjustGunForRobotTurn(true);
setAdjustRadarForGunTurn(true);
```

Put these two lines before the loop, after the round counter.

## Checkpoint

The robot now finds the enemy and keeps looking at it. It does not move or fire yet. If you
build and run it against `sample.SittingDuck`, the radar should settle on the duck and stay
there.
