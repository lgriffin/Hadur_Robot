# Build and run it

## Verify

From the lab folder:

```bash
mvn -B verify
```

Maven compiles the class, runs any tests (there are none yet, so this is quick) and packages a
jar. **Passing looks like** a final block that ends:

```text
[INFO] BUILD SUCCESS
```

and a file `target/hadurling.Hadurling_0.1.jar`. If you see `BUILD FAILURE`, read the first
`[ERROR]` line; it names the file and line number. The most common slips in this lab are a
missing `import` and a misspelt method name.

## What is in the jar

```bash
unzip -l target/hadurling.Hadurling_0.1.jar
```

You should see `hadurling/Hadurling.class` and `hadurling/Hadurling.properties`. The
properties file is how Robocode learns a jar holds a robot: its name, its class, its version.

## Load it into Robocode

1. Copy `target/hadurling.Hadurling_0.1.jar` into the `robots` folder of your Robocode
   installation. (Or in Robocode: Options, Preferences, Development Options, and add your
   `target` folder to the robot path.)
2. Start Robocode and choose Battle, New. In the list, `hadurling.Hadurling 0.1` should appear.
3. Add it and `sample.SittingDuck`, then start the battle.

Expect: the radar finds the duck, Hadurling circles it, and a stream of small bullets hits
it. Open the robot console for Hadurling (click its name in the battle view) and you should see
`Round 1 of this battle`, `Round 2 of this battle`, and so on.

Now try `sample.Crazy` or `sample.Walls`. You will lose some rounds: that is expected. Head-on
aim cannot hit a robot that keeps changing speed. Hadurling will get better, lab by lab.

## If Robocode does not list the robot

- The jar must be in `robots`, not in a sub-folder.
- Use Robocode 1.9.5.6. A much older one may not read the properties file.
- Restart Robocode, or choose Robot, Refresh in the new battle dialog.
