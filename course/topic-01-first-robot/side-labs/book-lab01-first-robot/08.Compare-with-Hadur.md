# Compare with Hadur

You wrote about 90 lines. Hadur's robot class does the same job, with the same shape. Open it
at the 3.5.1 release:

- [`hadur-robot/src/main/java/hadur2/Hadur.java`](https://github.com/lgriffin/Hadur_Robot/blob/a9ee021/hadur-robot/src/main/java/hadur2/Hadur.java)

Look for these, which you have just met:

| Hadurling (lab 01) | Hadur |
|---|---|
| `public class Hadurling extends AdvancedRobot` | `public class Hadur extends AdvancedRobot` |
| `@Override public void run()` with a `while (true)` loop that ends in `execute()` | the same loop, in `run()` |
| `private static int roundsStarted` survives rounds | `private static HadurCore core;` survives rounds: everything Hadur has learned is in it |
| `onScannedRobot`, `onHitWall` | the same handlers, one for each event Hadur cares about |
| `setAdjustGunForRobotTurn(true)` | the same two lines before the loop |
| `setTurnRadarRightRadians`, `setAhead`, `setFire` | in `apply`, one method that turns orders into those calls |

## What is different

Two things stand out, and they are the next three labs.

1. **Hadur does not decide anything in its event handlers.** Each handler only adds a small
   value to a list called `pending`. The decisions happen in one place per tick, from one input
   to one set of orders. Hadurling puts its decisions inside `onScannedRobot`, which is the
   quickest way to start and the hardest to test. Lab 03 fixes that.
2. **The strategy is not in this class at all.** `Hadur.java` imports `hadur2.core.*` for the
   brain and only translates. The brain, `HadurCore`, never imports `robocode`. That is the
   hexagon, and Lab 04 builds it.

Read the class comment of `Hadur` in full. It describes one tick as four steps. By Lab 04
Hadurling does the same four.

The architecture notes describe the same idea at the level of the whole project:
