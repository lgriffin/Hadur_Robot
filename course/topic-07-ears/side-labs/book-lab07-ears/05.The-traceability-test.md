# The traceability test

Now the glue that makes IDs a contract. `RequirementsTraceabilityTest` does four things:

1. reads `docs/requirements.md` and collects the IDs;
2. scans the test sources and feature files, collecting every tag;
3. fails if a requirement has no test;
4. fails if a tag names a requirement that does not exist.

Create it in `hadurling-core/src/test/java/hadurling/core/trace/`. Walk through the file in pieces.

## Finding the table and the tests

```java
    static final Pattern ROW = Pattern.compile("^\\|\\s*(HL-\\d+)\\s*\\|([^|]*)\\|(.*)\\|\\s*$");
    /** A JUnit or jqwik tag in Java source. */
    static final Pattern JAVA_TAG = Pattern.compile("@Tag\\(\"(HL-\\d+)\"\\)");
    /** A Cucumber tag on a feature line. */
    static final Pattern FEATURE_TAG = Pattern.compile("@(HL-\\d+)\\b");
    // Split so this file's own source cannot match them.
    static final String JQWIK_PROPERTY = "import net.jqwik.api." + "Property;";
    static final String JUNIT_TAG = "import org.junit.jupiter.api." + "Tag;";
```

A **regular expression** (`Pattern`) describes a shape of text. Take `ROW`:

- `^\|` the line starts with `|`
- `\s*(HL-\d+)\s*` optional spaces, then **group 1**: `HL-` and digits, e.g. `HL-3`
- `\|([^|]*)\|` the pattern cell (any characters except `|`)
- `(.*)\|\s*$` the rest, up to a final `|`

In Java source the backslashes are doubled (`"\\|"`) because a backslash is also an escape
in Java strings. `JAVA_TAG` finds `@Tag("HL-3")`, and `FEATURE_TAG` finds `@HL-3`.

## Reading files

```java
    @BeforeAll
    static void scan() throws IOException {
        root = findRoot();
        requirements = readRequirements(root.resolve("docs/requirements.md"));
        coverage = new TreeMap<>();
        junitTaggedProperties = new ArrayList<>();
        for (String module : List.of("hadurling-core", "hadurling-robot")) {
            Path tests = root.resolve(module).resolve("src/test");
            if (!Files.isDirectory(tests)) continue;
            try (Stream<Path> files = Files.walk(tests)) {
                for (Path f : (Iterable<Path>) files::iterator) {
                    String name = f.getFileName().toString();
                    if (name.endsWith(".java") && !name.equals("RequirementsTraceabilityTest.java")) {
                        collect(f, JAVA_TAG);
                        String src = read(f);
                        if (src.contains(JQWIK_PROPERTY) && src.contains(JUNIT_TAG)) {
                            junitTaggedProperties.add(root.relativize(f).toString());
                        }
                    } else if (name.endsWith(".feature")) {
                        collectFeature(f);
                    }
                }
            }
        }
        writeReport();
    }
```

`Files.walk` visits every file under a folder; the test looks at the ones that end in `.java` or `.feature`.
It also looks in `hadurling-robot` in case you put tests there. The file that holds the checker itself is
skipped, so the patterns do not match their own text.

`findRoot()` walks up from the folder the tests run in (the module) until it finds
`docs/requirements.md`. That makes the test work wherever Maven starts.

## The checks

```java
    @Test
    @DisplayName("every requirement is covered by a test")
    void everyRequirementIsCovered() {
        Set<String> missing = new TreeSet<>(requirements.keySet());
        missing.removeAll(coverage.keySet());
        assertTrue(missing.isEmpty(), "No test names " + missing);
    }

    @Test
    @DisplayName("every tag names a real requirement")
    void everyTagIsARequirement() {
        Set<String> unknown = new TreeSet<>(coverage.keySet());
        unknown.removeAll(requirements.keySet());
        assertTrue(unknown.isEmpty(), "Tags with no requirement: " + unknown + " in "
            + unknown.stream().map(coverage::get).collect(java.util.stream.Collectors.toList()));
    }
```

`removeAll` is set subtraction: the requirements minus the covered ones is what is missing. The
test fails with the missing IDs *in the message*, so you know exactly what to do. A
`TreeSet` keeps the message sorted.

A third check protects against the jqwik trap of step 3: if a file imports jqwik's `Property`
and JUnit's `Tag`, fail.

## The report

The test also writes `target/requirements-coverage.md`, a table of each requirement and the files that
name it. After a build:

```text
| ID | Covered by |
|---|---|
| HL-1 | ArchitectureTest.java |
| HL-2 | DeterminismTest.java, ReplayTest.java |
| HL-3 | CoreTest.java, hadurling.feature |
...
```

A reader can see the cover at a glance, and a reviewer can ask why `HL-1` has only one test.

## What it does not do

It checks that a test is **named** for a requirement, not that the test is any good. A tag on a
test that asserts nothing passes this check. It is a net, not a proof; reviewing the tests is
still a human job. But it does stop the most common failure: a requirement quietly forgotten.
