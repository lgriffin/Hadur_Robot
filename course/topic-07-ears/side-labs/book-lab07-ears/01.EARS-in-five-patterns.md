# EARS in five patterns

"The robot should dodge well" is a wish. You cannot write a test for it, and two people will
read it two ways. **EARS** (the Easy Approach to Requirements Syntax) fixes this with a few
sentence templates. Each starts with a keyword that says *when* the requirement applies, then
says what *the system* shall do:

| Pattern | Template | Example from Hadur |
|---|---|---|
| Ubiquitous | The `<system>` shall `<response>`. | CORE-1: The core shall not import any class from `robocode.*`. |
| Event-driven | **When** `<trigger>`, the `<system>` shall `<response>`. | MEM-1: When the first scan of a battle names an opponent, the core shall load the profile for that opponent's lineage key before producing orders for that tick. |
| State-driven | **While** `<state>`, the `<system>` shall `<response>`. | DIST-1: While our rolling hit rate exceeds the enemy's by 5 points or more, the distance policy shall reduce the target distance by 25 px per wave, not below 400 px. |
| Unwanted behaviour | **If** `<condition>`, **then** the `<system>` shall `<response>`. | WAVE-2: If a corrected energy drop is outside [0.1, 3.0], then the core shall not create a firing wave. |
| Optional feature | **Where** `<feature is present>`, the `<system>` shall `<response>`. | POW-1: Where the profile's gun tier is T0 and enemy energy exceeds 12, the gun shall fire power 3.0. |

These are quoted from Hadur's `docs/requirements.md` (3.5.1). Hadur's table calls the patterns
Ubiquitous, Event, State, Unwanted and Optional.

## Why bother?

- **One sentence, one behaviour.** The keyword forces you to say whether it is always true, true on
  an event, true in a state, a defence against a fault or an option.
- **A test can follow it.** "When X, shall Y" is a test: make X happen, check Y. "While X" is a test
  with a precondition. "If X, then Y" is a fault-injection test.
- **A stable ID.** `HL-3` never changes meaning. A planner can say "implement HL-3 and HL-4";
  whoever builds it ties the tests to `HL-3`. The ID is the contract. If the wording needs
  a fix, the ID keeps its history.

Try classifying these before you read on:

1. "While the gun is hot, the core shall hold fire." *(state-driven)*
2. "The core shall return equal orders for equal inputs." *(ubiquitous)*
3. "If a transcript line is malformed, then the codec shall reject it." *(unwanted behaviour)*
4. "Where a recorded battle is supplied, the replay shall reproduce it." *(optional feature)*
5. "When the robot hits a wall, the core shall reverse." *(event-driven)*
