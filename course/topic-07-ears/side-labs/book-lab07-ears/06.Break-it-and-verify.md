# Break it, and verify

## Verify

```bash
mvn -B verify
```

**Passing looks like**: the core's tests run, `CucumberTest` prints `3 Scenarios (3 passed)`, and the
traceability class reports 4 tests, all green. Then:

```bash
cat hadurling-core/target/requirements-coverage.md
```

Every requirement should list at least one file.

## Break it, three ways

A checker you have never seen fail is a guess. Do these in turn and restore each time.

**1. An untested requirement.** Delete the line `@Tag("HL-7")` from `LineCodecTest`. Run
`mvn -B verify -pl hadurling-core`. Expect:

```text
RequirementsTraceabilityTest.everyRequirementIsCovered
No test names [HL-7]
```

**2. An unknown ID.** Change one `@Tag("HL-6")` in `GuardTest` to `@Tag("HL-9")`. Expect:

```text
Tags with no requirement: [HL-9] in [[GuardTest.java]]
```

(HL-6 is still covered by two other tests, so only the unknown tag fails.)

**3. A new requirement.** Add `| HL-9 | Optional feature | Where ... |` to the table without a
test. Expect `No test names [HL-9]`. This is how a planner would add work: write the
requirement; the build goes red until someone writes the test.

Restore everything and check that `mvn -B verify` is green.

## The loop this creates

```text
planner: writes HL-9 in the table        ->  build is red
implementer: writes a failing test @HL-9 ->  build is red for a better reason
implementer: makes it pass               ->  build is green
```

The ID is all the two people share. That is why it must be stable.
