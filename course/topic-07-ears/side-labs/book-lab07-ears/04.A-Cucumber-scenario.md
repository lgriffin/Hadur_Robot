# A Cucumber scenario

Some requirements read better as a story a non-programmer can follow. **Cucumber** runs
specifications written in plain English (**Gherkin**), each sentence matched to a snippet of Java.

## Dependencies

In the parent `pom.xml`, add `<cucumber.version>7.20.1</cucumber.version>` to the properties, and
import the Cucumber BOM (a list of matching versions) in `<dependencyManagement>`:

```xml
<dependency>
    <groupId>io.cucumber</groupId>
    <artifactId>cucumber-bom</artifactId>
    <version>${cucumber.version}</version>
    <type>pom</type>
    <scope>import</scope>
</dependency>
```

In `hadurling-core/pom.xml`, test scope, three more dependencies: `junit-platform-suite`,
`cucumber-java` and `cucumber-junit-platform-engine` (all versions come from the BOMs).

## The feature file

Create `hadurling-core/src/test/resources/features/hadurling.feature`:

```gherkin
Feature: Hadurling's core
  The core decides from an Input alone, and a guard makes sure a decision always exists.

  @HL-3
  Scenario: The radar overshoots the enemy
    Given an enemy 45 degrees to our right
    When the core takes a tick
    Then the radar turns 90 degrees to the right

  @HL-4
  Scenario: A hot gun holds fire
    Given an enemy dead ahead
    And the gun heat is 0.4
    When the core takes a tick
    Then the core holds fire

  @HL-6
  Scenario: A failing core does not leave the robot without orders
    Given a core that always throws
    When the guard takes three ticks
    Then every tick has orders that drive 100 pixels ahead and hold fire
    And exactly 1 FAULT line was logged
```

`@HL-3` above a scenario is a **Cucumber tag**: the same idea, a different syntax (a bare `@` and
the ID). The scenario is a sentence that a planner could have written: *Given* a situation,
*When* something happens, *Then* a result.

## The glue

Each sentence needs Java behind it:

```java
    @Given("an enemy {int} degrees to our right")
    public void enemyToTheRight(int degrees) {
        enemyBearing = Math.toRadians(degrees);
    }

    @Given("an enemy dead ahead")
    public void enemyAhead() {
        enemyBearing = 0;
    }

    @Given("the gun heat is {double}")
    public void gunHeat(double heat) {
        gunHeat = heat;
    }

    @When("the core takes a tick")
    public void coreTick() {
        Event scan = new Event.Scan("foe", enemyBearing, 200, 100, 0, 0);
        orders = new Core().tick(new Input(1, 400, 300, 0, 0, 100, gunHeat, 0, 0, List.of(scan)));
    }

    @Then("the radar turns {int} degrees to the right")
    public void radarTurns(int degrees) {
        assertEquals(Math.toRadians(degrees), orders.radarTurn(), 1e-9);
    }
```

The text in the annotation is matched against the sentence; `{int}` captures a number and passes it
as a parameter. Fields in the class carry state from step to step (a new object is made for each
scenario). Copy the whole `CoreSteps` and `CucumberTest` from `course-labs/lab-07`.

`CucumberTest` is a **suite** that tells JUnit to run the Cucumber engine over `features/`:

```java
@Suite
@IncludeEngines("cucumber")
@SelectClasspathResource("features")
@ConfigurationParameter(key = GLUE_PROPERTY_NAME, value = "hadurling.core.steps")
@ConfigurationParameter(key = PLUGIN_PROPERTY_NAME, value = "summary")
class CucumberTest {
```

It ends in `Test`, so Maven runs it. Run `mvn -B test -pl hadurling-core` and look for:

```text
3 Scenarios (3 passed)
11 Steps (11 passed)
```

## When to use which

Use plain JUnit for developer-facing detail and Cucumber when the sentence is worth showing to
someone else: it is the readable layer. Hadur uses both, and its feature files are the
behaviours listed in its requirements.
