# Lab 07: Requirements as code

Tests tell you the code does *something*. Requirements say what it *should* do. In this lab you
write eight requirements for Hadurling in a precise, small language called **EARS**, give each a
stable ID, tag the tests that prove it, and write a test that fails the build when the two drift
apart: a requirement nobody tests, or a tag that names a requirement that does not exist.

## Objectives

By the end of this lab you can:

- write requirements in the five EARS patterns, and name the pattern of any sentence
- give a requirement a stable ID that tests can point at
- tag JUnit tests, jqwik properties and Cucumber scenarios with requirement IDs
- write a test that reads Markdown and Java source with regular expressions and file I/O
- explain why the ID is the contract between whoever plans a feature and whoever builds it

## What you start from

`course-labs/lab-06`, or this lab's [`start.zip`](./archives/start.zip).

## What you will have at the end

- `docs/requirements.md` with requirements `HL-1` to `HL-8`
- tests tagged `@Tag("HL-n")`, and `features/hadurling.feature` with `@HL-n` scenarios
- Cucumber 7.20.1 wired in (`CucumberTest`, `CoreSteps`)
- `RequirementsTraceabilityTest`, which writes `target/requirements-coverage.md`
- no change to the main code

This is `course-labs/lab-07`.
