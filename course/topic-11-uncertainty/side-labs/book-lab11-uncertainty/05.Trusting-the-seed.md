# Trusting the seed

In lab 10 the gun started a battle with up to 100 samples from the profile. That helps when the
opponent is the same robot it was last time, and hurts when it has changed. The gun needs a way to
stop believing the seed when the live battle says it is wrong, without throwing it away on a bad
afternoon.

`SeedTrust` holds a **weight** from 1 down to 0. At 1 the gun weighs seeded samples like live ones.
At 0 it ignores them. Each time the live evidence contradicts the profile, the weight falls by a
twentieth; it never grows back.

```java
public boolean diverges(Estimate live) {
    if (!live.within(MAX_LIVE_MARGIN) || Double.isNaN(profile.value())) return false;
    double margin = Math.max(live.margin(), profile.margin());
    return Math.abs(live.value() - profile.value()) > margin;
}

public boolean observe(Estimate live) {
    if (!diverges(live)) return false;
    divergedWaves++;
    if (decayedWaves >= DECAY_WAVES) return false;
    decayedWaves++;
    return true;
}

public double weight() {
    return decayedWaves >= DECAY_WAVES ? 0 : (DECAY_WAVES - decayedWaves) / (double) DECAY_WAVES;
}
```

It judges only when the live evidence is narrow (`within(MAX_LIVE_MARGIN)`, a margin of 0.10 or
less) and the profile says something. The two are compared against the wider of their margins.
"Differs by more than the wider margin" is requirement `HL-29`. Thin live evidence, or a profile
with nothing in it, never contradicts anything (`HL-30`).

## The rule that can never fire

Here is a mistake that is easy to make. Suppose `MAX_LIVE_MARGIN` was 0.05 and the window holds 100
outcomes. The widest margin a window of 100 can have is about 0.096 (at a 50% rate). A rule that
needs a margin of 0.05 or less would **never fire at all**, however wrong the profile was. Every
test that checked "it holds back on thin evidence" would pass. The code would be correct and the
rule would be dead.

Hadur met a bug of this kind: review of pull request #61 found a gate (`POW-4`) that could not be
reached, and the fix was commit `38cbf21`. The cure is a test of the rule's *reachability*, and in
Hadurling it is the first test in `SeedTrustTest`:

```java
@Test
@DisplayName("the rule can fire at all: a full window of 100 shots is narrow enough to judge")
void aFullWindowCanJudge() {
    assertTrue(full(20).within(SeedTrust.MAX_LIVE_MARGIN), "margin " + full(20).margin());
    assertTrue(full(50).within(SeedTrust.MAX_LIVE_MARGIN), "the widest case, a 50% rate: margin " + full(50).margin());
}
```

It builds the widest case a full window can produce and asks whether the rule would be willing to
judge it. If someone tightens the constant, this test fails for the right reason. Write a "can it
fire" test for every rule that holds back.

## The other tests

- live evidence that disagrees takes a twentieth off per wave, and nothing is left after twenty
  (`HL-29`, with the weight checked exactly: 0.95 after the first wave, 0 after twenty)
- thin live evidence cannot contradict the profile, however far off it is (`HL-30`)
- live evidence that agrees with the profile leaves the weight alone (`HL-30`)
- a profile with nothing in it cannot be contradicted (`HL-30`)
- the weight never grows back (`HL-29`)

## The gun uses the weight

`GuessFactorGun` marks each sample as seeded or live, and the weight multiplies a seeded sample's
vote:

```java
double weight = b.value().seeded ? seedWeight : 1;
double z = (a.value().factor - b.value().factor) / BANDWIDTH;
density += weight * Math.exp(-z * z);
```

At weight 0 the seeded samples are skipped as candidates too, and they do not count towards the
five samples the gun needs before it trusts the tree (`HL-31`).
