## ArchUnit for `policy`

Two rules, as for every new package:

```java
@Test
@DisplayName("policy is a leaf: it depends on nothing of Hadurling's but itself")
void policyIsALeaf() {
    classes().that().resideInAPackage("hadurling.core.policy..")
        .should().onlyDependOnClassesThat().resideInAnyPackage("hadurling.core.policy..", "java..")
        .check(core);
}

@Test
@DisplayName("only the core uses the policies: the gun, movement, ledger and memory do not")
void onlyTheCoreUsesPolicy() {
    noClasses().that().resideInAnyPackage("hadurling.core.gun..", "hadurling.core.move..",
            "hadurling.core.ledger..", "hadurling.core.memory..", "hadurling.core.model..",
            "hadurling.core.physics..", "hadurling.core.knn..", "hadurling.core.port..")
        .should().dependOnClassesThat().resideInAPackage("hadurling.core.policy..")
        .check(core);
}
```

The first keeps a policy testable with plain numbers. The second means the gun cannot decide its own
power, which would split the decision across two places.

## Check the hold-back claims yourself

The point of the lab is that the policies hold back. Check it by breaking one:

1. In `Estimate.of`, remove the `+ 2` and `+ 4` (use the plain rate and `n`). Which tests fail?
2. In `PowerPolicy.certain`, replace `lower()` with `value()`. Which tests fail? Is it the
   ones you expected?
3. Put both back.
