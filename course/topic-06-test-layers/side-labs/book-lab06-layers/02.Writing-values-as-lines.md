# Writing values as lines

Create the package `hadurling.core.replay` in the core (main) and `LineCodec.java` in it. The
format is plain text:

```text
I,time,x,y,heading,velocity,energy,gunHeat,gunHeading,radarHeading,event;event;...
O,bodyTurn,ahead,gunTurn,radarTurn,firePower
```

An `I` line is an `Input`; an `O` line is an `Orders`. An event is a letter and its fields,
separated by colons: `S:name:bearing:distance:energy:heading:velocity` for a scan, `W:bearing`
for a wall hit, and so on. Each line is one tick. A transcript of a battle is just two lines per tick.

## Doubles

```java
b.append(',').append(d);
```

`StringBuilder.append(double)` uses `Double.toString`, which writes **enough digits to read back
as exactly the same bits**, including `NaN`, `Infinity` and `-0.0`. You get exactness for free.

Writing floating point numbers in a fixed number of decimals (say, `%.3f`) would be tempting
and would be wrong: a replay would then differ in the fourth decimal and the codec property
would fail.

## Encoding an Input

```java
    public static String encode(Input in) {
        StringBuilder b = new StringBuilder("I");
        b.append(',').append(in.time());
        for (double d : new double[] {in.x(), in.y(), in.heading(), in.velocity(), in.energy(),
                in.gunHeat(), in.gunHeading(), in.radarHeading()}) {
            b.append(',').append(d);
        }
        b.append(',');
        for (int i = 0; i < in.events().size(); i++) {
            if (i > 0) b.append(';');
            b.append(encode(in.events().get(i)));
        }
        return b.toString();
    }
```

Do the same for `Orders` (`"O," + o.bodyTurn() + ...`), and for events:

```java
    private static String encode(Event e) {
        if (e instanceof Event.Scan) {
            Event.Scan s = (Event.Scan) e;
            return "S:" + escape(s.name()) + ":" + s.bearing() + ":" + s.distance() + ":"
                + s.energy() + ":" + s.heading() + ":" + s.velocity();
        }
        if (e instanceof Event.HitByBullet) {
            Event.HitByBullet h = (Event.HitByBullet) e;
            return "H:" + escape(h.shooter()) + ":" + h.power();
        }
        if (e instanceof Event.BulletHit) {
            Event.BulletHit h = (Event.BulletHit) e;
            return "B:" + escape(h.victim()) + ":" + h.power();
        }
        if (e instanceof Event.HitWall) return "W:" + ((Event.HitWall) e).bearing();
        if (e instanceof Event.RobotDeath) return "D:" + escape(((Event.RobotDeath) e).name());
        throw new IllegalArgumentException("unknown event " + e);
    }
```

## Names that contain separators

A robot's name can be anything: `sample.Crazy (1)` has spaces and brackets and might contain a
comma. If a name contained `:` or `;` the line would be ambiguous. So names are **escaped**:

```java
    static String escape(String s) {
        StringBuilder b = new StringBuilder();
        for (char c : s.toCharArray()) {
            if (c == '%' || c == ',' || c == ';' || c == ':' || c == '\n' || c == '\r') {
                b.append('%').append(String.format("%02X", (int) c));
            } else {
                b.append(c);
            }
        }
        return b.toString();
    }
```

`%` followed by two hex digits is the same idea as URL encoding. Escaping `%` itself is
essential: otherwise `%2C` in a real name would be read back as a comma.

`String.format("%02X", (int) c)` prints the character code in hexadecimal, at least two digits.
The inverse is the `unescape` method; `Integer.parseInt(text, 16)` reads hex back.
