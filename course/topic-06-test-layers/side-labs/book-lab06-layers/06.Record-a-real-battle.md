# Record a real battle

A scripted transcript is a fine regression test, but the real thing is better: the inputs a real
Robocode battle produced. Add a recorder to the robot module.

## Two hooks in the adapter

In `Hadurling.java` add two empty methods and call them:

```java
        roundStarted(getRoundNum());

        while (true) {
            Input in = input();
            Orders orders = guard.tick(in);
            ticked(in, orders);
            apply(orders);
            execute();
    }
```

and the hooks themselves:

```java
    protected void roundStarted(int round) { }

    /**
     * Called every tick after the core has decided and before the orders are applied. Does
     * nothing here; {@link HadurlingRecorder} uses it to write the tick down.
     *
     * @param in the input the core was given
     * @param orders the orders it returned (or the guard's safe orders)
     */
    protected void ticked(Input in, Orders orders) { }
```

A `protected` method can be overridden in a subclass but not called from outside. Robot code
does nothing in them, they exist so a **subclass** can watch. This is the **template method**
idea: the base class fixes the sequence and leaves holes.

## The recorder

```java
package hadurling;

import hadurling.core.model.Input;
import hadurling.core.model.Orders;
import hadurling.core.replay.LineCodec;
import java.io.IOException;
import java.io.PrintWriter;
import robocode.RobocodeFileWriter;
import robocode.RoundEndedEvent;

/**
 * Hadurling with a tape recorder. It fights exactly as {@link Hadurling} does and also writes
 * every tick's {@code Input} and {@code Orders} to {@code transcript.txt} in its data folder,
 * in the format of {@link LineCodec}. Copy the file into a core module's
 * {@code src/test/resources/replay/} and a real battle becomes a replay test.
 *
 * <p>Robocode gives a robot a small data quota (200 KB by default), so a long battle is cut
 * short: record two or three rounds. The recorder lives in the same jar as the robot; it
 * is a second robot, {@code hadurling.HadurlingRecorder}, with its own properties file.</p>
 */
public class HadurlingRecorder extends Hadurling {

    private PrintWriter tape;

    @Override
    protected void roundStarted(int round) {
        try {
            // Append, so one battle's rounds end up in one file. A second battle adds to it:
            // delete the file between battles.
            tape = new PrintWriter(new RobocodeFileWriter(getDataFile("transcript.txt").getPath(), true));
            tape.println("R," + round);
        } catch (IOException e) {
            out.println("recorder: " + e);
            tape = null;
        }
    }

    @Override
    protected void ticked(Input in, Orders orders) {
        if (tape == null) return;
        tape.println(LineCodec.encode(in));
        tape.println(LineCodec.encode(orders));
    }

    /**
     * Flushes the tape. Writing to a file is allowed here but not in {@code run()} after
     * the round has ended, so this is where it is closed.
     *
     * @param e the engine's report
     */
    @Override
    public void onRoundEnded(RoundEndedEvent e) {
        try {
            super.onRoundEnded(e);
        } finally {
            if (tape != null) {
                tape.close();
                tape = null;
            }
        }
    }
}
```

`HadurlingRecorder extends Hadurling`: it *is* Hadurling, plus a tape. It uses the `LineCodec`
you just wrote. It needs its own properties file, `HadurlingRecorder.properties`, so Robocode
lists it as a second robot:

```properties
#Robocode Robot Properties
robot.description=Hadurling with a replay transcript, for capturing test fixtures.
robot.author.name=course
robot.classname=hadurling.HadurlingRecorder
robot.version=0.1
robocode.version=1.9.5.6
```

## Use it

1. Build with `mvn -B verify` and copy the jar to Robocode's `robots` folder.
2. Fight `hadurling.HadurlingRecorder` against `sample.Crazy` for two or three rounds.
3. Find `transcript.txt` in Robocode's data folder for the robot (under
   `robots/.data/hadurling/HadurlingRecorder.data/` in a default install).
4. Copy it into `hadurling-core/src/test/resources/replay/` with a name such as
   `sample.Crazy.txt`, and add a test that replays it, as `ReplayTest` does.

Robocode limits a robot's data folder to a small quota (200 KB), so record a short battle. If the
recorder cannot write the file it prints a message to its console instead of crashing.

Because the file is whatever the robot **actually did**, any later change of the core that alters an
order will fail the replay. You will have to decide: is the change a bug, or an intended
improvement? If it is intended, you record a new transcript. The test turns "did my refactor
change behaviour?" into a yes or no.
