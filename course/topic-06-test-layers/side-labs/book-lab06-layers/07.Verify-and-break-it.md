# Verify, and break the core on purpose

```bash
mvn -B verify
```

**Passing looks like**: the core's test count rises (41 to 53: the codec properties and
tests, five replay tests), `Failures: 0`, and `BUILD SUCCESS`. jqwik prints a short INFO line
about edge cases; that is normal.

## Break the core to see the replay catch it

The scripted duel fires a few times. Change the fire power in `HeadOnGun`:

```java
public static final double POWER = 2.0;   // was 1.0
```

and run `mvn -B verify -pl hadurling-core`. Expect:

```text
ReplayTest.replayMatchesRecording ==> line 13 ==> expected: <Orders[... fire=1.0]> but was: <Orders[... fire=2.0]>
```

The message names the line of the transcript. Did any **unit** test fail? Probably `CoreTest`
expects `HeadOnGun.POWER` as a constant, not 1.0, so it passes: it checks the core is consistent
with itself. The replay is the only layer that noticed the change in behaviour. That is its job.
Set the power back to `1.0`.

## Break the codec to see the property catch it

In `LineCodec.escape`, stop escaping the comma. The round-trip property fails with a short name
containing a comma, after shrinking. The scripted transcript's one robot name, `sample.Crazy (1)`,
has no comma, so replay would **not** have noticed. That is the layering at work: each test
sees what the others cannot. Undo.

## Where each of today's tests lives

| Test | Layer | Catches |
|---|---|---|
| `LineCodecTest` | unit | the format as written, bad input |
| `LineCodecProperties` | property | any value that fails to round-trip |
| `ReplayTest` | replay | any change of the core's orders on a recorded battle |
