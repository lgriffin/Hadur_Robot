# Properties with custom generators

Round-trip is the classic property: `decode(encode(x)) == x` for every `x`. To test it we need
jqwik to make `Input`s and `Orders`. We tell it how, with **providers**.

Create `LineCodecProperties.java` in `src/test/java/hadurling/core/replay/`.

## Generators

```java
    /** Mostly ordinary numbers, but also the awkward ones. */
    @Provide
    Arbitrary<Double> doubles() {
        return Arbitraries.oneOf(
            Arbitraries.doubles().between(-1e6, 1e6),
            Arbitraries.of(Double.NaN, Double.POSITIVE_INFINITY, Double.NEGATIVE_INFINITY, 0.0, -0.0));
    }

    /** Names that contain every character the codec must escape. */
    @Provide
    Arbitrary<String> names() {
        return Arbitraries.strings().withChars("abcXYZ019 .()-%,;:\n").ofMinLength(1).ofMaxLength(12);
    }
```

- An `Arbitrary<T>` is a recipe for making random `T`s. `@Provide` marks a method that returns one;
  a property then asks for it by name: `@ForAll("doubles")`.
- `Arbitraries.oneOf(a, b)` picks one of several recipes at random: here half the values are ordinary
  numbers and half come from a short list of awkward ones (`NaN`, both infinities, both zeros). Without
  the second recipe jqwik would almost never produce `NaN`, and a codec that mishandles `NaN` would
  pass.
- The `names` generator draws only from a small alphabet that **contains every character the
  codec must escape**: `% , ; :` and a newline. Random strings from the whole of Unicode would
  almost never include a comma. A good generator aims where the bugs live.

## Building bigger values

```java
    @Provide
    Arbitrary<Event> events() {
        Arbitrary<Event> scan = Combinators.combine(names(), doubles(), doubles(), doubles(), doubles(), doubles())
            .as(Event.Scan::new);
        Arbitrary<Event> hitBy = Combinators.combine(names(), doubles()).as(Event.HitByBullet::new);
        Arbitrary<Event> bulletHit = Combinators.combine(names(), doubles()).as(Event.BulletHit::new);
        Arbitrary<Event> wall = doubles().map(Event.HitWall::new);
        Arbitrary<Event> death = names().map(Event.RobotDeath::new);
        return Arbitraries.oneOf(scan, hitBy, bulletHit, wall, death);
    }
```

`Combinators.combine(a, b, ...).as(constructor)` builds an object from several recipes at once:
`Event.HitByBullet::new` is a **constructor reference**, a short way to say `(n, p) -> new
Event.HitByBullet(n, p)`. `Arbitraries.oneOf(...)` of the five event recipes makes any event.

For `Input`, with ten fields, combine a time, a list of eight doubles and a list of events:

```java
    @Provide
    Arbitrary<Input> inputs() {
        return Combinators.combine(
                Arbitraries.longs().between(0, 100_000),
                doubles().list().ofSize(8),
                events().list().ofMaxSize(4))
            .as((t, d, ev) -> new Input(t, d.get(0), d.get(1), d.get(2), d.get(3), d.get(4),
                d.get(5), d.get(6), d.get(7), ev));
    }
```

(The combine call is limited to eight arguments, which is why the doubles come as one
list of eight.)

## The properties

```java
    @Property
    void inputRoundTrips(@ForAll("inputs") Input in) {
        assertEquals(in, LineCodec.decodeInput(LineCodec.encode(in)));
    }

    @Property
    void ordersRoundTrip(@ForAll("orders") Orders o) {
        assertEquals(o, LineCodec.decodeOrders(LineCodec.encode(o)));
    }

    @Property
    void namesRoundTrip(@ForAll("names") String name) {
        assertEquals(name, LineCodec.unescape(LineCodec.escape(name)));
    }
```

Each is one line of logic. A fourth property in the file checks that an encoded line never
contains a line break, because a transcript is one line per record.

## Shrinking

Make `encode` forget to escape a comma in names and run the tests. jqwik finds a failing case
quickly, then **shrinks** it: it tries simpler and simpler inputs that still fail, until it
reports something like a `Scan` with the name `","`. You did not write that example; the library
found the smallest one for you. Undo the damage.
