# The library's index

Open `ProfileLibrary.makeRoom` as it was in lab 12:

```java
List<String> names = store.names();
long others = 0;
for (String name : names) {
    if (!name.equals(own) && !name.equals(own + TMP_SUFFIX)) others += store.size(name);
}
```

On every save it lists the store, then asks every file for its size. On disk that is a directory
scan and a `stat` per file. With 700 profiles, that is 700 stats per save, and a robot saves at the
end of every round. This is the slide.

## The idea

Nothing about the store changes between saves except what **this library** does to it. So list it
**once**, remember what you saw, and keep the memory up to date as you save and delete.

```java
private Map<String, long[]> index;   // name -> {size, age}
private TreeSet<String> byAge;       // names, oldest first
private long used;                   // total bytes
private long clock;                  // a counter for new ages
```

The index is built the first time it is needed, and then kept:

```java
private void index() {
    if (index != null) return;
    index = new TreeMap<>();
    byAge = new TreeSet<>((a, b) -> {
        int byTime = Long.compare(index.get(a)[1], index.get(b)[1]);
        return byTime != 0 ? byTime : a.compareTo(b);
    });
    used = 0;
    for (String name : store.names()) {
        long age = store.lastModified(name);
        clock = Math.max(clock, age);
        put(name, store.size(name), age);
    }
}
```

This is the one listing. After it, `save` updates the index with each write and delete, and
`makeRoom` reads from it:

```java
private void makeRoom(String own, int needed) {
    index();
    long others = used - sizeOf(own) - sizeOf(own + TMP_SUFFIX);
    while (others + 2L * needed > store.quota()) {
        String oldest = null;
        for (String name : byAge) {
            if (isProfileFile(name) && !name.equals(own) && !name.equals(own + TMP_SUFFIX)) {
                oldest = name;
                break;
            }
        }
        if (oldest == null) throw new IllegalStateException("a profile of " + needed + " bytes does not fit");
        others -= sizeOf(oldest);
        store.delete(oldest);
        remove(oldest);
    }
}
```

The oldest profile is the first name in `byAge`: no scan. That is `HL-41`.

## Two traps

**The order of operations in `remove`.** The ordered set finds a name by comparing ages, and the ages
live in the map. So take the name out of the set **before** you take it out of the map. Reverse them
and `byAge.remove` cannot find the name, and the set quietly keeps a dead entry.

```java
private void remove(String name) {
    long[] old = index.get(name);
    if (old == null) return;
    byAge.remove(name);
    index.remove(name);
    used -= old[0];
}
```

**A failure means the index may be wrong.** If a store call throws, we no longer know what is on disk.
`save` handles it by throwing the index away, so the next save lists again:

```java
} catch (RuntimeException e) {
    // We no longer know what is on disk: list again next time.
    index = null;
    saveFailures++;
    ...
}
```

A cache with no way to be wrong is a bug waiting. This one fails safe: the cost of doubt is one
listing, not a corrupt index.

`load` never touches the index at all. It reads two files by name.
