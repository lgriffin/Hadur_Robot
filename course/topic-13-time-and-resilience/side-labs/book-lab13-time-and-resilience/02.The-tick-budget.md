# The tick budget

`TickBudget` turns "how long did the last tick take, and did the engine skip a turn" into one
number, a **level** from 0 (do everything) to 3 (do the least). It is a small state machine with no
clock in it.

```java
public static final long ALLOWANCE_NANOS = 3_000_000L;
public static final double THRESHOLD = 0.70;
public static final int MAX_LEVEL = 3;

public void tickTook(long usedNanos) {
    slow = usedNanos > THRESHOLD * ALLOWANCE_NANOS;
    if (slow) slowTicks++;
    maxLevel = Math.max(maxLevel, level());
}

public void skippedTurn() {
    roundLevel = Math.min(MAX_LEVEL, roundLevel + 1);
    maxLevel = Math.max(maxLevel, level());
}

public int level() {
    return Math.min(MAX_LEVEL, roundLevel + (slow ? 1 : 0));
}
```

The allowance is a guess: 3 ms. Robocode does not tell a robot its own allowance, so the constant is
a number chosen to be safe on a slow machine. Say so in the comment, because the guess is what a
reader will ask about.

Two kinds of memory:

- `slow` is for the **next tick only**. The following call to `tickTook` replaces it. That is
  `HL-36`.
- `roundLevel` goes up on each skipped turn and **stays** for the rest of the round. That is `HL-37`.
  A new `TickBudget` is made for each round (as the `Core` is), so it starts again at 0.

The level is the sum of the two, capped at 3.

## What each level sheds

The budget only says how much work the core may do. The core asks it two plain questions:

```java
public static int neighbours(int level, int full) {
    if (level >= 3) return 0;
    return level >= 1 ? Math.max(1, full / 2) : full;
}

public static boolean surfs(int level) {
    return level < 2;
}
```

| Level | Gun | Surfer |
|-------|-----|--------|
| 0 | all neighbours | predicts |
| 1 | half the neighbours | predicts |
| 2 | half the neighbours | does not predict |
| 3 | head-on, no tree | does not predict |

The order matters. The cheapest thing to give up first is the one that costs least accuracy.

## Test every edge

`TickBudgetTest` has one test per sentence of the requirements:

```java
@Test
@Tag("HL-36")
@DisplayName("a tick over 70% of the allowance sheds one level, for the next tick only")
void slowTickCostsOneTick() {
    TickBudget budget = new TickBudget();
    budget.tickTook((long) (0.71 * ALLOWANCE));
    assertEquals(1, budget.level());
    budget.tickTook((long) (0.30 * ALLOWANCE));
    assertEquals(0, budget.level());
    assertEquals(1, budget.slowTicks());
}
```

- a new budget is at full computation
- a tick at exactly 70% sheds nothing (`HL-36`; the edge, on the right side)
- a skipped turn sheds a level for the rest of the round, up to three (`HL-37`)
- a slow tick on top of skips never passes the deepest level (`HL-37`)
- each level sheds more (`HL-38`)

Test 0.71 and 0.70, not just 0.9 and 0.1: bugs are at the line.
