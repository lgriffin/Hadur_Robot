# Lab 13: Time and resilience

Two kinds of slowness hurt a robot, and both are quiet. The first is the **tick**: Robocode gives
each robot a small slice of CPU every turn, and a robot that overruns skips a turn and loses a
shot or a move. The second is the **slide**: a design that is fine with ten files on disk and slow
with a thousand, so a robot that has fought many opponents gets slower with every battle. In this
lab you build a budget that sheds work when ticks run long, and you change the profile library so
that saving a profile costs the same however many profiles are stored.

## Objectives

By the end of this lab you can:

- explain why the core may not read a clock, and how time still reaches it
- write a tick budget that degrades the robot in steps, and test each step
- replay a slow battle exactly, because timing is part of the recording
- find a cost that grows with the size of the store, and remove it with an index
- test a cost without timing it, by counting the thing that grows

- `hadurling.core.policy.TickBudget`, and two new events, `TickTime` and `SkippedTurn`

- requirements `HL-36` to `HL-41`

- a replay fixture that is unchanged
