# Time comes in as an event

The core must not read a clock (`HL-39`). If it did, a replay of the same recording would behave
differently on a faster computer, and the best test in the project, the replay, would stop being a
test. But the core needs to know about time. So the adapter, which is allowed a clock, reads it and
passes the reading in as an ordinary event.

## Two new events

In `model/Event.java`:

```java
public static final class TickTime extends Event {
    private final long nanos;
    public TickTime(long nanos) { this.nanos = nanos; }
    public long nanos() { return nanos; }
    // equals, hashCode, toString
}

public static final class SkippedTurn extends Event {
    // equals, hashCode, toString
}
```

Then add them to the replay format so that a recording carries them. `LineCodec` writes
`T:<nanos>` and `K`:

```java
if (e instanceof Event.TickTime) return "T:" + ((Event.TickTime) e).nanos();
if (e instanceof Event.SkippedTurn) return "K";
...
case "T":
    need(f, 2);
    return new Event.TickTime(Long.parseLong(f[1]));
case "K":
    need(f, 1);
    return new Event.SkippedTurn();
```

`LineCodecProperties` (the round-trip property from the earlier lab) gets the two events in its
generator, so every round trip now includes them. `LineCodecTest` gets an example of each.

Because timing is in the recording, **a replay of a slow battle sheds the same work**. That is the
reward for making time an input. The scripted duel in `ScriptedBattle` has no timing events, so its
budget stays at level 0 and the replay fixture does not change.

## The adapter times its own call

In `Hadurling.run`, wrap the call into the guard:

```java
Input in = input();
// The core may not read a clock (HL-39), so the adapter times it and reports the
// measurement with the next tick's events.
long started = System.nanoTime();
Orders orders = guard.tick(in);
lastTickNanos = System.nanoTime() - started;
ticked(in, orders);
apply(orders);
execute();
```

and report it with the next tick's events:

```java
if (lastTickNanos >= 0) pending.add(new Event.TickTime(lastTickNanos));
```

Robocode tells the robot about a skipped turn through a callback; turn it into an event too:

```java
@Override
public void onSkippedTurn(SkippedTurnEvent e) {
    pending.add(new Event.SkippedTurn());
}
```

Only the time spent **in the core** is measured, not the time Robocode spends between turns. That is
the part the robot controls.

## Enforce it

The "no clock" rule is an ArchUnit test, and it now carries a tag:

```java
@Test
@Tag("HL-39")
@DisplayName("no clock: time comes in on the Input")
void noClock() {
    noClasses().that().resideInAPackage(CORE)
        .should().callMethod(System.class, "currentTimeMillis")
        .orShould().callMethod(System.class, "nanoTime")
        .check(core);
}
```

A requirement that says "shall not" is best enforced by a rule that fails the build.
