# Exercises

## 1. Ban System.out

The core should not print: the `Telemetry` port exists for that. Add a rule that no class in the
core accesses the field `System.out` or `System.err`. (Use `.accessField(System.class, "out")`
inside a `noClasses()` rule.) Then add `System.out.println("hi")` to the core to see it fail, and
remove it.

## 2. No mutable statics

A `static` field that changes is hidden state, and two `Core`s would share it, which would break the
determinism test only if you ran them in the same JVM, like the tests do. Add a rule that every
`static` field in the core is `final`:

```java
fields().that().areDeclaredInClassesThat().resideInAPackage("hadurling.core..")
    .and().areStatic()
    .should().beFinal()
    .check(core);
```

(`fields()` comes from `ArchRuleDefinition`.) Does the main code pass? What about `Telemetry.NONE`?

## 3. Only the JDK

Add a rule that the core depends on nothing outside `hadurling.core..`, `java.lang..` and
`java.util..`. The `resideOutsideOfPackages` predicate does it. You will find a few more
`java.*` packages the code uses; allow them one at a time and ask whether you really want them.

## 4. A custom check

Write a test (plain JUnit) that reads the source of every file under `hadurling-core/src/main/java` and fails if
any contains the text `TODO`. Is that a good rule? When would it get in the way? Compare it to
the ArchUnit rules: which are easier to read, and which give the best error message?
