# Rules nobody checks are wishes

Write down what the core must never do:

1. Never depend on `robocode.*`.
2. Never use a random number generator we did not seed.
3. Never start or wait on a thread.
4. Never read or write files or the network.
5. Never read the clock.
6. The model and the physics are at the bottom: they must not depend on the gun or the movement.
7. The gun and the movement do not know each other.

Rules 2 to 5 have one reason in common: **determinism**. If the core's orders depend on a dice
roll, the time of day or the contents of a file, then a recorded battle replayed tomorrow gives
different orders, a bug you saw once cannot be reproduced, and a test can fail by chance. Rule 1
is the hexagon. Rules 6 and 7 keep the dependency arrows tidy: otherwise, over a year, every
package ends up depending on every other.

You could write these into a document and trust people to remember. Hadur's lesson, and this lab's, is the
opposite: **the build is the reviewer that never gets tired**. If a rule can be checked by a
program, check it by a program, on every build.

## ArchUnit

**ArchUnit** is a library that reads compiled `.class` files and lets you write assertions
about them in Java:

```java
noClasses().that().resideInAPackage("hadurling.core..")
    .should().dependOnClassesThat().resideInAnyPackage("robocode..")
    .check(classes);
```

It reads like the rule you wrote on paper. `..` means "this package and everything below it".
Because ArchUnit inspects bytecode, it also catches uses you cannot see in source: a field type,
a method call, a superclass.
