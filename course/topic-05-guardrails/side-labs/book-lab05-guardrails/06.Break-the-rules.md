# Break each rule on purpose

A rule you have never seen fail may not be checking anything. A good habit: break it, see it go
red, read the message, and put the code back. Do each of these once.

## 1. Robocode in the core

Add to `Core.java`: `import robocode.util.Utils;` and use it, say
`Utils.normalRelativeAngle(0)` somewhere. Run:

```bash
mvn -B verify -pl hadurling-core
```

It does not even compile: the main code has no Robocode on its classpath. That is the module
boundary of Lab 04 doing its work. (ArchUnit's rule 1 is the second line of defence: it would
catch a class that sneaked in through another route.)

## 2. A random number

Add a field to `Core`:

```java
private final java.util.Random dice = new java.util.Random();
```

Run the same command. You get:

```text
Architecture Violation [Priority: MEDIUM] - Rule 'no classes that reside in a package
'hadurling.core..' should call method Math.random() or should depend on classes that have
fully qualified name 'java.util.Random' or ...' was violated (2 times):
Constructor <hadurling.core.Core.<init>()> calls constructor <java.util.Random.<init>()> in (Core.java:24)
Field <hadurling.core.Core.dice> has type <java.util.Random> in (Core.java:0)
```

Read it as a sentence: the rule, how many times it was broken, and *where*, with the class,
the member and the line. This is the message a colleague gets when they break your rule on a
Friday afternoon, so the rule's `@DisplayName` and shape matter.

## 3. A layer

In `HeadOnGun.java`, add `import hadurling.core.move.Orbit;` and a field `Orbit orbit = new Orbit();`.
The test "the gun and the movement do not depend on each other" fails and names the field.

## 4. The clock

In `Core.tick`, add `long t = System.nanoTime();`. The clock rule fails on the call.

Put everything back and make sure `mvn -B verify` is green again before you carry on.
