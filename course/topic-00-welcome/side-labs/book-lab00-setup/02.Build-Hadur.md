# Build Hadur

You will build the real Hadur robot from source. This proves your tools work, and gives you the jar you will fight with in the next step.

## Clone

```sh
git clone https://github.com/lgriffin/Hadur_Robot.git
cd Hadur_Robot
```

## Build and test everything

```sh
mvn verify
```

This runs, in order: the ArchUnit rules, the jqwik properties, the unit tests, the replay of recorded battles, the Cucumber scenarios and the traceability test, then builds the robot jar. The first run downloads dependencies, so give it a few minutes. Later runs are quicker.

You are looking for `BUILD SUCCESS` at the end. If a test fails, read the first failure, not the last.

## Find the jar

The robot jar is here:

```text
hadur-robot/target/hadur2.Hadur_<version>.jar
```

The version is the `robot.release` property in `hadur-robot/pom.xml`. It was `3.9` when this course was last updated, so the file you get is:

```text
hadur-robot/target/hadur2.Hadur_3.9.jar
```

If master has moved on, the number is higher; use the jar you have in the steps that follow. The same build also writes `hadur2.HadurTeam_3.9.jar`, the TeamRumble entry: five Hadurs in one team. You will not need it in this course.

The core is bundled inside it. Check it is there:

```sh
ls hadur-robot/target/*.jar
```

## Why the jar is Java 11

The repository's root `pom.xml` compiles the robot with `maven.compiler.release` 11 and the tests with `maven.compiler.testRelease` 17. That is why you can build with JDK 17 and still produce a robot that every RoboRumble client can load.

## Check yourself

- `mvn verify` ends in `BUILD SUCCESS`
- You can see `hadur2.Hadur_<version>.jar` under `hadur-robot/target/`
