# The ledger

Create `hadurling/core/ledger/EnergyLedger.java`. It remembers the enemy's last energy and speed,
collects what it is told about hits during the interval, and answers one question at each scan:
was there a shot?

## Its inputs

```java
public void ourBulletHit(double power) {
    ourDamage += Rules.bulletDamage(power);
}

public void enemyBulletHitUs(double power) {
    refund += 3 * power;
}
```

Hits come in from the core as events arrive, before the scan. The ledger sums them.

## The scan

```java
public Reading scan(double enemyEnergy, double enemyVelocity) {
    Reading reading;
    if (Double.isNaN(energy)) {
        reading = new Reading(0, 0, 0, false);
    } else {
        double raw = energy - enemyEnergy;
        double wall = wallDamage(velocity, enemyVelocity);
        double corrected = raw - ourDamage + refund - wall;
        boolean shot = corrected >= MIN_SHOT - TOLERANCE && corrected <= MAX_SHOT + TOLERANCE;
        reading = new Reading(raw, corrected, wall, shot);
    }
    energy = enemyEnergy;
    velocity = enemyVelocity;
    ourDamage = 0;
    refund = 0;
    return reading;
}
```

Read the arithmetic as a statement of what happened. `raw` is how far the energy fell. Our hits
explained some of it, so take them off. The refund made the fall look smaller, so put it back. The
wall hit explained some more, so take that off. What is left is `corrected`.

Three details that matter:

- **The first scan has nothing to compare with.** It can never be a shot.
- **The hits are cleared every interval.** A hit explains one drop only. A test pins this down.
- **A tolerance of `1e-9` at the edges.** Powers 0.1 and 3.0 are legal shots, and floating-point
  arithmetic would otherwise make 0.1 look like 0.09999999999.

## Inferring a wall hit

The ledger is not told about a wall hit. It infers one from the speed:

```java
static double wallDamage(double before, double after) {
    if (Double.isNaN(before) || after != 0 || Math.abs(before) <= MAX_BRAKING) return 0;
    return Math.max(0, Math.abs(before) / 2 - 1);
}
```

A robot that was going fast and is now stopped hit something. A robot that merely braked can lose
at most `MAX_BRAKING` (2) of speed in a tick, so a stop from 2 or less is ordinary braking. This is
an inference, and like all inferences it can be wrong, which is why you test it from both sides in
step 4.

## What the Reading carries

`Reading` has four fields: `raw`, `corrected`, `wallDamage` and `shot`. The core only needs `shot`
and `corrected`. The rest are there so that a test failure tells you what the ledger thought.
`Reading.toString` prints all four for exactly that reason.

The ledger imports only `physics.Rules`. Step 7 turns that into a rule.
