# A property: our angles equal the engine's

A unit test checks examples you thought of. A **property** states a rule that must hold for
**every** input, and a library tries thousands of random inputs, including nasty ones, to find
a counter-example. This is **property-based testing**; jqwik is the library.

Our claim: for any angle, `Angles.normalRelativeAngle` gives exactly what
`robocode.util.Utils.normalRelativeAngle` gives. If that is true, we can replace the engine's
helper without changing the robot's behaviour by one bit.

Create `src/test/java/hadurling/physics/AnglesMatchEngineProperties.java`:

```java
package hadurling.physics;

import static org.junit.jupiter.api.Assertions.assertEquals;

import net.jqwik.api.ForAll;
import net.jqwik.api.Property;
import net.jqwik.api.constraints.DoubleRange;
import robocode.util.Utils;

/**
 * Our angle helpers must equal the engine's for every input, not just the ones we thought
 * of. jqwik generates thousands of angles (and edge cases such as 0 and PI) per property.
 */
class AnglesMatchEngineProperties {

    @Property
    void relativeAngleMatchesEngine(@ForAll @DoubleRange(min = -100, max = 100) double angle) {
        assertEquals(Utils.normalRelativeAngle(angle), Angles.normalRelativeAngle(angle), 0.0);
    }

    @Property
    void absoluteAngleMatchesEngine(@ForAll @DoubleRange(min = -100, max = 100) double angle) {
        assertEquals(Utils.normalAbsoluteAngle(angle), Angles.normalAbsoluteAngle(angle), 0.0);
    }

    @Property
    void bulletSpeedMatchesEngine(@ForAll @DoubleRange(min = 0.1, max = 3.0) double power) {
        assertEquals(robocode.Rules.getBulletSpeed(power), Rules.bulletSpeed(power), 1e-12);
    }

    @Property
    void bulletDamageMatchesEngine(@ForAll @DoubleRange(min = 0.1, max = 3.0) double power) {
        assertEquals(robocode.Rules.getBulletDamage(power), Rules.bulletDamage(power), 1e-12);
    }
}
```

## Reading it

- `@Property` instead of `@Test`: jqwik runs the method many times (1000 by default).
- `@ForAll` on a parameter: jqwik generates its values. `@DoubleRange` limits them. jqwik
  adds edge cases of its own, such as 0, -0.0 and the range limits.
- The last argument `0.0` is the tolerance: we demand **exact** equality, since our code is a
  copy of the engine's.
- The file name ends in `Properties`, so Maven's surefire plugin runs it.

The engine's classes are on the test classpath because the API dependency is `provided`. A
test may use them even though the robot's main code, from Lab 04 on, will not.

## Make it fail

Break `Angles.normalRelativeAngle` on purpose: change `angle < Math.PI ? angle` to
`angle < 3.14 ? angle`, run `mvn -B test`, and read the output. jqwik reports a **shrunk**
counter-example, the simplest failing input it found; here it is about 3.14, and the message
reads `expected: <3.14> but was: <-3.143185307179586>`. The ordinary unit tests would probably
have passed: nobody writes a test for 3.14. Shrinking is the library's best feature. A failing random test gives you the smallest case,
not a random mess. Undo the change.

If a property ever fails and you fix the bug, jqwik also remembers the failing input in the
database file we set to `target/.jqwik-database`, and tries it first next time.
