# Use it in the robot, and verify

Switch `Hadurling` from the engine's helper to your own. In `Hadurling.java`:

1. Replace `import robocode.util.Utils;` with `import hadurling.physics.Angles;`.
2. Replace each `Utils.normalRelativeAngle` with `Angles.normalRelativeAngle`.
3. Where we computed the enemy's direction, fold it into the compass range:

```java
// Where the enemy is, as a compass direction rather than relative to our heading.
double enemyDirection = Angles.normalAbsoluteAngle(getHeadingRadians() + e.getBearingRadians());
```

Imports in Java are sorted alphabetically by convention: `hadurling...` goes before `robocode...`.

## Verify

```bash
mvn -B verify
```

**Passing looks like**: Maven prints a block per test class, the numbers of tests run add up
(4 + 4 + 3 + 4 = 15 here), `Failures: 0, Errors: 0`, and ends with `BUILD SUCCESS`. To see each
test class on its own, look in `target/surefire-reports/`.

If something fails, read the first failure only. Later ones are often echoes of it.

## Behaviour must not change

The point of a safe refactor is that the robot behaves the same. Run the same battle as in
Lab 01 and check that Hadurling still circles and shoots. If it does not, the property test
from step 6 should have caught it: that is what it is for.

You can now explain to someone why they can trust your `Angles`. Not "I wrote it carefully" but
"it equals the engine's on tens of thousands of random angles, on every build".
