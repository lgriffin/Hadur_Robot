# Set up the test layout

Maven expects a fixed layout, and following it means no configuration:

```text
src/main/java/...   the code that ships in the robot jar
src/test/java/...   tests; never shipped
src/test/resources  files only tests need
```

Test classes live in the **same package** as the class they test, but in `src/test/java`. So
`hadurling.physics.Angles` is tested by `hadurling.physics.AnglesTest`. Being in the same
package lets a test use package-private members.

## Dependencies

The pom already has JUnit 5 and the Robocode API. Add the property-testing library **jqwik**
inside `<dependencies>`, next to JUnit. First declare its version in `<properties>`:

```xml
<jqwik.version>1.9.2</jqwik.version>
```

then:

```xml
<dependency>
    <groupId>net.jqwik</groupId>
    <artifactId>jqwik</artifactId>
    <version>${jqwik.version}</version>
    <scope>test</scope>
</dependency>
```

`<scope>test</scope>` means the library is on the classpath while tests run, and absent from the
robot jar. Remember the Robocode API has `<scope>provided</scope>`: it is there to compile
against, and the engine supplies it at run time. Our tests can use it too, which matters in
step 6.

The pom's surefire plugin (the one that runs tests) already includes any class whose name ends
in `Test`, `Tests` or `Properties`. Name your jqwik classes `...Properties` and they run.

Add one more file, `src/test/resources/junit-platform.properties`, to keep jqwik quiet on a
green run and to keep its failure database inside `target`:

```properties
jqwik.reporting.onlyfailures=true
jqwik.database=target/.jqwik-database
```

Create the packages `hadurling.physics` under both `src/main/java` and `src/test/java`.
