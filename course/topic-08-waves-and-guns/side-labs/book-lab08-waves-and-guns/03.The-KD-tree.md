# The k-d tree

The gun will ask one question many times a second: "which past shots were fired in a situation
most like this one?" Measuring every past shot is fine for 10 of them and slow for 2000. A k-d tree
answers faster by splitting space one axis at a time.

Create `hadurling-core/src/main/java/hadurling/core/knn/KdTree.java`. It depends on nothing else of
Hadurling's, which an ArchUnit rule in step 7 will insist on.

## Adding a point

Each node holds a point and splits on one axis. A new point goes left if it is smaller on that axis
and right otherwise, and the next level down splits on the next axis.

```java
public boolean add(double[] point, T value) {
    check(point);
    if (size >= capacity) return false;
    double[] copy = point.clone();
    if (root == null) {
        root = new Node<>(copy, value, 0);
    } else {
        Node<T> node = root;
        while (true) {
            boolean goLeft = copy[node.axis] < node.point[node.axis];
            Node<T> next = goLeft ? node.left : node.right;
            if (next == null) {
                Node<T> fresh = new Node<>(copy, value, (node.axis + 1) % dimensions);
                if (goLeft) node.left = fresh; else node.right = fresh;
                break;
            }
            node = next;
        }
    }
    size++;
    return true;
}
```

Two details to copy. The tree keeps its own copy of the array, so a caller cannot change a stored
point afterwards. And it has a `capacity`: when full, `add` returns false and changes nothing. A
robot that learns for 35 rounds must not run out of memory.

## Searching

Search goes down the near side first, keeping the best `k` found so far in a heap. The far side is
only worth visiting if the splitting plane is closer than the worst point we are keeping:

```java
double gap = query[node.axis] - node.point[node.axis];
Node<T> near = gap < 0 ? node.left : node.right;
Node<T> far = gap < 0 ? node.right : node.left;
search(near, query, k, best);
if (best.size() < k || gap * gap < best.peek().distance) search(far, query, k, best);
```

That one `if` is the whole trick. It is also where a bug would hide: if the comparison were wrong
the tree would silently skip a closer point. The next step catches that.

Distance is the squared Euclidean distance. Nobody takes the square root, because the order of
distances is the same without it.

## Know the weakness

This tree does not rebalance. Insert points in sorted order and it leans into a linked list, and a
search costs as much as a scan. Hadur's tree keeps buckets of points and splits them when they
fill, which avoids this. Hadurling's gun gets points in an unpredictable order, so it can live with
the simple tree. Exercise 3 asks you to show the weakness.
