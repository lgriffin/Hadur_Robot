# The surfer and the shot detector

The same `Wave` now works the other way round: an enemy bullet is a wave aimed at us.

## The surfer

Create `hadurling/core/move/Surfer.java`. It remembers the guess factors at which enemy bullets hit
us, and when a wave is coming it asks which way round the enemy we should go to land on a safer
guess factor.

```java
public int choose(Input in, int current) {
    Wave wave = soonest(in);
    if (wave == null) return current;
    double clockwise = danger(predictedFactor(wave, in, +1));
    double anticlockwise = danger(predictedFactor(wave, in, -1));
    if (Math.abs(clockwise - anticlockwise) < 1e-9) return current;
    return clockwise < anticlockwise ? +1 : -1;
}

double danger(double factor) {
    double sum = 0;
    for (double h : hits) {
        double z = (factor - h) / BANDWIDTH;
        sum += Math.exp(-z * z);
    }
    return sum;
}
```

Danger at a guess factor is how many past hits were near it. With no history both ways are equally
safe, so the surfer keeps going the way it was (`HL-12` has a test for this). It never flips a coin.

Add two small methods to `Orbit` so the surfer's choice can be applied: `direction()` returns +1 or
-1, and `face(int)` sets it.

## The shot detector

How does the core know the enemy fired? Fired bullets cost energy: a bullet of power `p` takes `p`
off the shooter. If the enemy's energy drops by between 0.1 and 3.0 between two scans, treat it as a
shot. This goes in `Core`:

```java
private void watchEnemyEnergy(Input in, Event.Scan scan, double enemyDirection) {
    boolean fresh = lastScanInput != null && in.time() - lastScanTime <= 2;
    double drop = lastEnemyEnergy - scan.energy();
    if (fresh && drop >= Rules.MIN_BULLET_POWER && drop <= Rules.MAX_BULLET_POWER) {
        double toUs = Angles.absoluteBearing(lastEnemyX, lastEnemyY, lastScanInput.x(), lastScanInput.y());
        double lateral = lastScanInput.velocity() * Math.sin(lastScanInput.heading() - toUs);
        surfer.enemyFired(new Wave(lastEnemyX, lastEnemyY, lastScanTime, drop, toUs, Wave.direction(lateral)));
    }
    ...
}
```

The wave starts where the enemy was at the last scan and is aimed at where we were then. The
`fresh` check stops it comparing against a stale energy after a long gap.

This is requirement `HL-13`, and it is naive. Two things make it wrong in a real fight: our own
bullets that hit also lower the enemy's energy, and the enemy loses energy to wall hits and
collisions too. Lab 09 replaces it with an energy ledger. Keep this one simple.

## Wire it into the tick

In `Core.tick`, replace `HeadOnGun` with the new gun and call the surfer:

```java
if (e instanceof Event.HitByBullet) surfer.hitBy(in);
...
surfer.advance(in);
if (in.time() - lastWallHit > WALL_COOLDOWN) orbit.face(surfer.choose(in, orbit.direction()));
...
gun.observe(in, scan);
GuessFactorGun.Aim aim = gun.aim(in, scan);
orders.gunTurn(aim.turn());
orders.fire(aim.power());
```

The wall cooldown (20 ticks) stops the surfer undoing a wall-hit reversal straight away and
driving back into the wall. That is a bug you only find by watching a battle, so it is worth a line
of comment in your code.

`Core` is still free of Robocode imports and still deterministic. The next step proves it.
