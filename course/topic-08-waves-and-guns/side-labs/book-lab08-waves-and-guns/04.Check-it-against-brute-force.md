# Check it against brute force

How do you test a data structure whose whole job is to be faster than the obvious method? You test
that it gives the same answer as the obvious method. This is a **model-based property**: a fast
structure must agree with a slow one that is clearly right. The slow one here is "measure every
point and sort".

Create `KdTreeProperties` in `hadurling.core.knn` (test source). Tag the class `HL-9`, using
jqwik's `Tag`, not JUnit's (you met the trap in lab 07).

```java
@Tag("HL-9")
class KdTreeProperties {

    /** A whole-number grid makes ties likely, which is where bugs hide. */
    @Provide
    Arbitrary<double[]> points() {
        return Arbitraries.integers().between(-5, 5).list().ofSize(3)
            .map(l -> new double[] {l.get(0), l.get(1), l.get(2)});
    }

    @Property
    void treeAgreesWithBruteForce(@ForAll("clouds") List<double[]> cloud,
            @ForAll("looseQueries") double[] query, @ForAll("kValues") int k) {
        KdTree<Integer> tree = new KdTree<>(3, 1000);
        for (int i = 0; i < cloud.size(); i++) tree.add(cloud.get(i), i);

        List<Double> expected = new ArrayList<>();
        for (double[] p : cloud) expected.add(KdTree.squaredDistance(p, query));
        Collections.sort(expected);
        expected = expected.subList(0, Math.min(k, expected.size()));

        List<Double> actual = new ArrayList<>();
        for (KdTree.Entry<Integer> e : tree.nearest(query, k)) actual.add(e.distance());

        assertEquals(expected, actual);
    }
}
```

Three choices worth copying:

- **The grid.** Points are whole numbers from -5 to 5, so many points sit at exactly the same
  distance. Ties are where tree code goes wrong, and random real numbers almost never make a tie.
- **Compare distances, not points.** Two points at the same distance may come back in either order,
  so "the same neighbours" is ambiguous. The sorted list of distances is not.
- **k from 0 to 12 and clouds up to 150 points.** That covers the empty tree, `k` larger than the
  tree, and `k` of zero.

## Break it

Open `KdTree.search`, change `gap * gap <` to `gap * gap >`, and run the property. jqwik finds a
cloud where the two disagree and shrinks it to a handful of points. Put the line back.

A few plain example tests go in `KdTreeTest`, also tagged `HL-9`: an empty tree returns nothing,
a full tree refuses a point, and a point of the wrong length throws.
