# Lab 04: The hexagon

Hadurling's `Brain` already has no `import robocode`, but nothing *stops* it from gaining one. In
this lab you build a wall that the compiler enforces: the brain moves to its own Maven module
that does not have Robocode on its classpath at all. You also add a safety net, the **Guard**,
so a bug in the brain can never leave the robot without orders.

## Objectives

By the end of this lab you can:

- turn a single Maven project into a parent pom with two modules, and say who depends on whom
- explain ports and adapters (the hexagonal architecture) using Hadurling as the example
- define a port as an interface, and implement it as a lambda
- use an exception boundary: catch everything at one place and answer with a safe default
- write a test double: a stand-in that fails on purpose
- package a robot jar that contains the core, with the Maven shade plugin
