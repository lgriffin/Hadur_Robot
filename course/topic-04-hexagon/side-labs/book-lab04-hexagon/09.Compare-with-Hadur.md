# Compare with Hadur

Hadur's hexagon first appeared in stage S1 of the rebuild, a commit you can open as it was:

- [`Guard`](https://github.com/lgriffin/Hadur_Robot/blob/afd6cc9/hadur-core/src/main/java/hadur2/core/Guard.java):
  your `Guard`, grown by experience. Same shape: a `Function`, a recover hook, a `Telemetry`,
  a `Throwable` catch and `safeOrders`. Find the fault counter and the `catch (Throwable t)`.
- [`GuardTest`](https://github.com/lgriffin/Hadur_Robot/blob/afd6cc9/hadur-core/src/test/java/hadur2/core/GuardTest.java):
  the same tests with a throwing core as a test double.
- [`HadurCore`](https://github.com/lgriffin/Hadur_Robot/blob/afd6cc9/hadur-core/src/main/java/hadur2/core/HadurCore.java):
  the equivalent of `Core`, the one object the adapter builds. In S1 it was small, like yours.
- [`port/Telemetry`](https://github.com/lgriffin/Hadur_Robot/blob/afd6cc9/hadur-core/src/main/java/hadur2/core/port/Telemetry.java):
  the same port. Hadur's version also has a second port for saving opponent profiles, added later.
- [`docs/architecture.md`](https://github.com/lgriffin/Hadur_Robot/blob/afd6cc9/docs/architecture.md),
  sections "Modules" and "Ports and values": the full picture, with the same diagram.

The module split itself is in the pom files:
[parent](https://github.com/lgriffin/Hadur_Robot/blob/afd6cc9/pom.xml),
[`hadur-core`](https://github.com/lgriffin/Hadur_Robot/blob/afd6cc9/hadur-core/pom.xml) and
[`hadur-robot`](https://github.com/lgriffin/Hadur_Robot/blob/afd6cc9/hadur-robot/pom.xml).
Find the Robocode API scope in each: `test` in the core, `provided` in the robot, as in yours.

## Notice

1. **The core is huge and the rule is the same.** Hadur's core has dozens of classes; the
   dependency rule on it has not changed since the S1 commit.
2. **The guard has no strategy.** It stayed tiny on purpose: the thing that protects you must not
   be able to fail for the reasons you are protecting against.
3. **Everything later hangs off this split.** The bench, the replay, the fuzzing and the
   property tests all call the core without an engine. That is the return on this lab.

Lab 05 turns the unwritten parts of the rule into tests the build runs.
