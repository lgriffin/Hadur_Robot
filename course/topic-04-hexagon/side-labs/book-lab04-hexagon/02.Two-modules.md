# Two modules

We turn the project into a **parent** with two **modules**. Do it with the shell, then edit the
poms.

## Move the files

From the lab folder:

```bash
C=hadurling-core/src; R=hadurling-robot/src
mkdir -p $C/main/java/hadurling/core $C/test/java/hadurling/core $C/test/resources
mkdir -p $R/main/java/hadurling $R/main/resources/hadurling $R/test/java/hadurling

# the brain moves into the core, and is renamed Core
mv src/main/java/hadurling/model    $C/main/java/hadurling/core/model
mv src/main/java/hadurling/physics  $C/main/java/hadurling/core/physics
mv src/main/java/hadurling/Brain.java $C/main/java/hadurling/core/Core.java
mv src/test/java/hadurling/model    $C/test/java/hadurling/core/model
mv src/test/java/hadurling/physics  $C/test/java/hadurling/core/physics
mv src/test/java/hadurling/BrainTest.java $C/test/java/hadurling/core/CoreTest.java
mv src/test/resources/junit-platform.properties $C/test/resources/

# the robot stays a robot
mv src/main/java/hadurling/Hadurling.java $R/main/java/hadurling/
mv src/main/resources/hadurling/Hadurling.properties $R/main/resources/hadurling/
rm -rf src      # everything has moved
```

Now every class in `model` and `physics` has the wrong package line. Fix them with search and
replace (your editor's "replace in files"), or with `sed`:

```bash
grep -rl hadurling hadurling-core hadurling-robot | xargs sed -i \
  's/hadurling\.model/hadurling.core.model/g; s/hadurling\.physics/hadurling.core.physics/g'
```

Then change `package hadurling;` to `package hadurling.core;` in `Core.java` and
`CoreTest.java`, and rename the class `Brain` to `Core`, and its `think` method to `tick`.

## The parent pom

Replace `pom.xml`. (The jar name from the old `<build>` section moves to the robot's pom in step 6.) The things to notice: `<packaging>pom</packaging>` (it builds no jar of its
own), the `<modules>` list, and `<dependencyManagement>`, which fixes the versions of
dependencies once so the modules need not repeat them.

```xml
    <packaging>pom</packaging>

    <name>Hadurling (lab 04)</name>
    <description>The Building Hadur course robot: a core with no Robocode, and an adapter.</description>

    <modules>
        <module>hadurling-core</module>
        <module>hadurling-robot</module>
    </modules>
```

and, in `<dependencyManagement>`, the versions of the core module, the Robocode API, the JUnit
BOM and jqwik. Copy the file from `course-labs/lab-04/pom.xml`; the parent also keeps the Java
versions (main code 11, test code 17) and the surefire setup in `<pluginManagement>`, so both
modules share them.

## The core's pom

Create `hadurling-core/pom.xml`:

```xml
    <dependencies>
        <!-- Test only: checks the core's physics against the engine's own helpers. The core's
             main code never sees Robocode. -->
        <dependency>
            <groupId>net.sf.robocode</groupId>
            <artifactId>robocode.api</artifactId>
            <scope>test</scope>
        </dependency>
        <dependency>
            <groupId>org.junit.jupiter</groupId>
            <artifactId>junit-jupiter</artifactId>
            <scope>test</scope>
        </dependency>
        <dependency>
            <groupId>net.jqwik</groupId>
            <artifactId>jqwik</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>
```

Study the Robocode dependency: its scope is **test**. The core's tests use `robocode.util.Utils`
to check `Angles` (Lab 02's property). But the *main* code is compiled without the API on its
classpath, so it cannot import it. Test code and main code have separate classpaths; this is the
whole trick.

## The robot's pom

`hadurling-robot/pom.xml` depends on the core, plus the Robocode API as `provided`. Its jar plugin
config comes in step 6. For now copy the `<dependencies>` block from `course-labs/lab-04`.

Check the split builds, even though some code is not written yet:

```bash
mvn -B -q compile -pl hadurling-core
```

`-pl` means "project list": build only that module. It fails now, because `Core` still has
`Brain`'s old package line; fix any remaining errors it reports before moving on.
