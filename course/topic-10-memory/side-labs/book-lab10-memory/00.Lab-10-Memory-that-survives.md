# Lab 10: Memory that survives

So far Hadurling forgets everything when the round ends. In this lab it keeps a **profile** of each
opponent on disk: how many shots each side fired and hit, and a small seed of what the gun learned.
The next round, and the next battle, start with that knowledge. Writing to disk from a robot that
can be killed at any moment is where the interesting engineering is. You will design a file format
that notices damage, a save that cannot lose the old profile, and tests that cut a write short on
purpose.

## Objectives

By the end of this lab you can:

- design a small binary format with a magic number, a version, a length and a CRC32 checksum
- decode it so that damaged input gives one checked exception and nothing else
- keep the file format behind a port, so the core never touches a disk
- write a fake store that can be killed part way through a write, and test every cut
- write the real store with `RobocodeFileOutputStream`

## What you start from

`course-labs/lab-09`, or this lab's `archives/start.zip`.

## What you will have at the end

- `hadurling.core.memory`: `Profile`, `ProfileCodec`, `ProfileFormatException`, `LineageKey`
  and `ProfileLibrary`
- `hadurling.core.port`: `ProfileStore` and `MemoryProfileStore`
- `hadurling.FileProfileStore` in the robot module
- requirements `HL-17` to `HL-24`
- the gun can be seeded from, and report what it learned to, a profile
- ArchUnit rules for `memory` and `port`
