# Real files and the core

## Lineage keys

An opponent's name looks like `sample.Walls 1.0` or `sample.Walls 1.0 (2)` (a duplicate in the
battle). Both are the same robot. `LineageKey.of` strips the version and the duplicate marker so
every version shares one profile:

```java
public static String of(String name) {
    if (name == null) return UNKNOWN;
    String s = name.length() > MAX_LENGTH ? name.substring(0, MAX_LENGTH) : name;
    s = stripDuplicateMarkers(s.trim());
    int space = s.indexOf(' ');
    // Drop the version only when what comes before it looks like package.Class.
    if (space > 0 && s.substring(0, space).indexOf('.') > 0) s = s.substring(0, space);
    return s.isEmpty() ? UNKNOWN : s;
}
```

`fileStem` turns the key into a file name that has only letters, digits, `.`, `-` and `_` and never
starts with a dot, then adds the hash of the whole key so that two keys that clean up to the same
text stay apart. `LineageKeyProperties` tags `HL-24` and checks arbitrary names, including ones full
of slashes and dots, never give an unsafe file name.

## The real store

In the robot module (not the core) write `FileProfileStore`. It takes an `Opener`, which is how a
file becomes an output stream:

```java
return new FileProfileStore(dir, used + robot.getDataQuotaAvailable(), RobocodeFileOutputStream::new);
```

Robocode's sandbox does not let a robot write with a plain `FileOutputStream`. It must use
`RobocodeFileOutputStream`, and it can only write inside its data directory. The `Opener` lets
tests substitute a stream that fails, so the class is tested without Robocode.

Two details to copy. Names are checked in one place:

```java
private File file(String name) {
    if (name.isEmpty() || name.contains("/") || name.contains("\\") || name.startsWith(".")) {
        throw new IllegalArgumentException("bad store name " + name);
    }
    return new File(dir, name);
}
```

That is `HL-22`, and `FileProfileStoreTest` tries names that would leave the directory. And `read`
loops until the buffer is full or the file ends, because `InputStream.read` is allowed to return
fewer bytes than you asked for.

Robocode reports the quota **left**, not the total, so `forRobot` adds back what is already on disk.

`FileProfileStoreTest` also runs the library over real temporary files with a stream cut short, to
check that "a save killed during the second write still loads the old profile".

## The core

`Core` gains a constructor that takes a `ProfileLibrary` (the no-argument one passes `null`, so
all earlier tests still work). Two moments matter:

```java
if (library != null && profile == null) meet(scan);

private void meet(Event.Scan scan) {
    profile = library.load(LineageKey.of(scan.name()));
    gun.seed(profile.seed());
}

public void roundEnded() {
    if (library == null || profile == null) return;
    List<float[]> learned = gun.learned();
    library.save(profile.afterRound(theirShots, theirHits, ourShots, ourHits, learned));
}
```

The first scan of an opponent loads its profile and seeds the gun; the end of the round saves what
was learned. The counts come from the outcomes that `surfer.advance` and `gun.observe` now return,
so `Core` also changed those two loops. `GuessFactorGun` gains `seed(List<float[]>)` and `learned()`:
the gun keeps every sample it files in a list so that it can hand them back.

`Hadurling` keeps the library in a `static` field. A robot object is rebuilt for each round, but the
JVM lasts the whole battle, so the library is opened once. In `onRoundEnded` the robot calls
`core.roundEnded()` inside a `try`, so a bug in saving cannot stop the next round.

`CoreTest` gets a test tagged `HL-23` that fakes a library over a `MemoryProfileStore`, plays a
round, ends it, and checks a second `Core` starts with the first one's samples.
