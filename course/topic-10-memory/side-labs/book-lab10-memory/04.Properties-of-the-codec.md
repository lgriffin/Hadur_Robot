# Properties of the codec

These tests ask for things that no hand-picked example could cover. Create `ProfileCodecProperties`
in the `memory` test package. Tag each property with its own `HL-n` (jqwik's `Tag`, as always).
First the profile generator:

```java
@Provide
Arbitrary<Profile> profiles() { ... }
```

It builds random keys, counts that obey "hits do not exceed shots", and a seed of up to 100 samples
of three floats. If the generator is wrong, the profile constructor throws, and you find out at once.

## Round trip (`HL-17`)

```java
@Property
@Tag("HL-17")
void decodingWhatWasEncodedGivesTheSameProfile(@ForAll("profiles") Profile p) throws Exception {
    assertEquals(p, ProfileCodec.decode(ProfileCodec.encode(p)));
}
```

This is why `Profile` has its own `equals`: it compares the seed arrays by content.

## Every cut is caught (`HL-18`)

```java
@Property
@Tag("HL-18")
void everyCutShortFileIsRejected(@ForAll("profiles") Profile p, @ForAll("fractions") double where) {
    byte[] bytes = ProfileCodec.encode(p);
    int keep = (int) (where * (bytes.length - 1));
    assertThrows(ProfileFormatException.class, () -> ProfileCodec.decode(Arrays.copyOf(bytes, keep)));
}
```

Keep any number of bytes from 0 to length minus 1, and the decoder must refuse. Not "usually".

## Every flipped bit is caught (`HL-18`)

```java
bytes[at] ^= (byte) (1 << bit);
assertThrows(ProfileFormatException.class, () -> ProfileCodec.decode(bytes));
```

CRC-32 detects every single-bit error, so this is a property that must hold for all positions.

## Nothing else escapes (`HL-18`)

```java
@Property
@Tag("HL-18")
void anyBytesAtAllGiveAProfileOrTheCodecsOwnException(@ForAll byte[] anything) {
    try {
        ProfileCodec.decode(anything);
    } catch (ProfileFormatException expected) {
        // Fine. Any other exception type would escape and fail the property.
    }
}
```

There is no assertion. The property fails if anything other than the checked exception comes out.
This is called a **robustness** or **fuzz** property, and it is the cheapest way to find the
`ArrayIndexOutOfBounds` you did not know you had.

## An older version loads (`HL-19`)

```java
@Property
@Tag("HL-19")
void aVersionOneFileLoadsWithTheNewFieldsAtDefaults(@ForAll("profiles") Profile p) throws Exception {
    Profile expected = new Profile(p.key(), p.rounds(), p.theirShots(), p.theirHits(), 0, 0, new ArrayList<>());
    assertEquals(expected, ProfileCodec.decode(ProfileCodec.encode(p, 1)));
}
```

Because `encode` takes a version, the test needs no stored file from the past. Also keep one example
test (`ProfileCodecTest`) with a hand-built version 1 byte array, so a mistake that affects
`encode(p, 1)` and `decode` in the same way cannot hide.

## Break it

Change `MAGIC_1`, or leave out the length check, and see which properties catch it, and how small the
shrunk counterexample is.
