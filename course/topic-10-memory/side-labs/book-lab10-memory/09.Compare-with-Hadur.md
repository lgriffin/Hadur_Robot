# Compare with Hadur

Hadur's memory arrived in stage S3. The format, the library and the store are the same design with
more in them.

- [`ProfileCodec`](https://github.com/lgriffin/Hadur_Robot/blob/a844960/hadur-core/src/main/java/hadur2/core/memory/ProfileCodec.java):
  find the magic number, the version and the checksum. Which fields does the newest version have
  that yours does not?
- [`ProfileCodecProperties`](https://github.com/lgriffin/Hadur_Robot/blob/a844960/hadur-core/src/test/java/hadur2/core/memory/ProfileCodecProperties.java):
  compare the properties with yours.
- [`LineageKey`](https://github.com/lgriffin/Hadur_Robot/blob/a844960/hadur-core/src/main/java/hadur2/core/memory/LineageKey.java):
  the same job for robot names.
- [`ProfileLibrary`](https://github.com/lgriffin/Hadur_Robot/blob/a844960/hadur-core/src/main/java/hadur2/core/memory/ProfileLibrary.java):
  the save and the load. Look for the order of the writes.
- [`ProfileStore`](https://github.com/lgriffin/Hadur_Robot/blob/a844960/hadur-core/src/main/java/hadur2/core/port/ProfileStore.java)
  and [`MemoryProfileStore`](https://github.com/lgriffin/Hadur_Robot/blob/a844960/hadur-core/src/main/java/hadur2/core/port/MemoryProfileStore.java):
  the port and its fake.
- [`FileProfileStore`](https://github.com/lgriffin/Hadur_Robot/blob/a844960/hadur-robot/src/main/java/hadur2/FileProfileStore.java)
  and its [test](https://github.com/lgriffin/Hadur_Robot/blob/a844960/hadur-robot/src/test/java/hadur2/FileProfileStoreTest.java):
  the real files and `RobocodeFileOutputStream`.

## Notice

1. **The fake fails on purpose.** The store that can be killed is the most important test double in
   the project, and it is twenty lines.
2. **The format is a promise.** Once a profile is on a disk in a battle you cannot recall, the
   format cannot change except by adding a version.
3. **Failing soft.** Nothing in the library throws to the core. A broken disk costs a lesson, not
   the battle.
