# The store and the killed save

The core must not know about disks. Define the port in `hadurling.core.port`:

```java
public interface ProfileStore {
    byte[] read(String name);          // null when there is no such file
    void write(String name, byte[] bytes);
    void delete(String name);
    List<String> names();
    long size(String name);
    long lastModified(String name);
    long quota();
}
```

It is deliberately small: bytes in, bytes out, with the quota visible so the library can make room.

## A fake that can be killed

`MemoryProfileStore` holds files in a map. Its job in tests is to fail on demand:

```java
public MemoryProfileStore crashOnWrite(int nth, int keepBytes) {
    this.crashAt = writes + nth;
    this.crashKeep = keepBytes;
    return this;
}

if (writes == crashAt) {
    int keep = Math.min(crashKeep, bytes.length);
    entries.put(name, Arrays.copyOf(bytes, keep));
    written.put(name, writes);
    throw new Crash("killed after " + keep + " bytes of " + name);
}
```

On the nth write from now it leaves **only a prefix** of the new bytes behind, and throws. That is
exactly what a robot killed in the middle of a stream does to a file. It also enforces the quota,
and it counts writes instead of using the clock, so tests are repeatable.

## The library saves in an order that cannot lose

```java
public boolean save(Profile profile) {
    try {
        byte[] bytes = ProfileCodec.encode(profile);
        String file = fileFor(profile.key());
        makeRoom(file, bytes.length);
        store.write(file + TMP_SUFFIX, bytes);
        store.write(file, bytes);
        store.delete(file + TMP_SUFFIX);
        return true;
    } catch (RuntimeException e) {
        saveFailures++;
        lastNote = "save " + profile.key() + ": " + e;
        return false;
    }
}
```

Three steps: write the new profile to a temporary copy, write it again over the real file, then
delete the copy. At every moment at least one complete good profile is on disk:

- killed during write 1: the real file is untouched, and the half-written copy fails its checksum
- killed during write 2: the real file fails its checksum, and the copy is complete
- killed during the delete: both are complete and equal

Loading mirrors it. Try the main file, then the copy, and take the first that decodes:

```java
for (byte[] bytes : new byte[][] {main, copy}) {
    if (bytes == null) continue;
    try {
        Profile p = ProfileCodec.decode(bytes);
        return p.key().equals(key) ? p : Profile.stranger(key);
    } catch (ProfileFormatException e) {
        lastNote = "load " + key + ": " + e.getMessage();
    }
}
loadFailures++;
return Profile.stranger(key);
```

The `key` check handles two opponents whose names map to the same file stem. And an outer
`catch (RuntimeException e)` turns a store that throws into a stranger and a counted failure
(`HL-21`). The library never throws to the core.

## Prove it, for every cut

This is the property that matters. Create `ProfileLibraryProperties`, tagged `HL-20`:

```java
@Property
void aSaveKilledAnywhereLeavesTheOldOrTheNewProfile(@ForAll("profiles") Profile before,
        @ForAll("profiles") Profile after, @ForAll("whichWrite") int nth,
        @ForAll("cutAt") double fraction) {
    MemoryProfileStore store = new MemoryProfileStore(1_000_000);
    assertTrue(new ProfileLibrary(store).save(before));

    int newSize = ProfileCodec.encode(after).length;
    store.crashOnWrite(nth, (int) (fraction * newSize));
    new ProfileLibrary(store).save(after); // may be cut short: it reports false and does not throw

    Profile loaded = new ProfileLibrary(store).load("a.Foe");
    assertTrue(loaded.equals(before) || loaded.equals(after),
        "loaded " + loaded + " after a save killed in write " + nth + " at " + fraction);
}
```

`whichWrite` picks write 1 (the temporary copy) or write 2 (the file itself). `cutAt` picks any
fraction of the new bytes from 0 to 1. A second property covers a first-ever save: the result is a
stranger or the new profile. A new library object does the load, to show nothing lived in memory.

Change the order of the two writes in `save` and run the property. It finds a cut that loses the
profile. The order is the safety.

## Make room

`makeRoom` deletes the least recently written other profiles until the new one (twice, because the
temporary copy and the real file exist together) fits in the quota. `ProfileLibraryTest` has the
examples: a saved profile loads back and the copy is gone; an unknown opponent is a stranger and
not a failure; a damaged file is a stranger and counted; a store that throws costs a lesson, not the
robot; a full store forgets the oldest other profile; and a profile too big for the quota fails to
save and the others survive.
