# The codec

Create `ProfileFormatException` (a checked exception, so a caller must decide what to do) and
`ProfileCodec`. The layout:

```
byte  'H'
byte  'P'
byte  version
int   payload length
...   payload
int   CRC32 of everything before it
```

Seven bytes of header, the payload, four bytes of checksum.

## Encode

```java
public static byte[] encode(Profile p, int version) {
    if (version < OLDEST_VERSION || version > VERSION) throw new IllegalArgumentException("version " + version);
    byte[] payload = payload(p, version);
    ByteBuffer b = ByteBuffer.allocate(HEADER + payload.length + TRAILER);
    b.put((byte) MAGIC_0).put((byte) MAGIC_1).put((byte) version).putInt(payload.length).put(payload);
    b.putInt(crc(b.array(), HEADER + payload.length));
    return b.array();
}
```

`encode(p)` is `encode(p, VERSION)`. Taking an explicit version looks like an odd luxury, but it is
how you test older versions in step 4: you write a version 1 file with the current code.

The payload differs by version:

```java
out.writeUTF(p.key());
out.writeInt(p.rounds());
out.writeInt(p.theirShots());
out.writeInt(p.theirHits());
if (version >= 2) {
    out.writeInt(p.ourShots());
    out.writeInt(p.ourHits());
    List<float[]> seed = p.seed();
    out.writeByte(seed.size());
    for (float[] sample : seed) {
        for (float f : sample) out.writeFloat(f);
    }
}
```

Version 1 had no `ourShots`, `ourHits` or seed. Version 2 appends them. **Appending is the whole
trick of a compatible format**: fields are only ever added at the end, so the old fields keep their
place.

## Decode: check from the outside in

```java
public static Profile decode(byte[] bytes) throws ProfileFormatException {
    if (bytes.length < HEADER + TRAILER) throw new ProfileFormatException("only " + bytes.length + " bytes");
    ByteBuffer b = ByteBuffer.wrap(bytes);
    if ((b.get() & 0xFF) != MAGIC_0 || (b.get() & 0xFF) != MAGIC_1) throw new ProfileFormatException("not a profile");
    int version = b.get() & 0xFF;
    if (version < OLDEST_VERSION || version > VERSION) throw new ProfileFormatException("unknown version " + version);
    int length = b.getInt();
    if (length < 0 || length > MAX_PAYLOAD || HEADER + length + TRAILER != bytes.length) {
        throw new ProfileFormatException("length field " + length + " does not match " + bytes.length + " bytes");
    }
    int stored = ByteBuffer.wrap(bytes, bytes.length - TRAILER, TRAILER).getInt();
    if (stored != crc(bytes, bytes.length - TRAILER)) throw new ProfileFormatException("checksum mismatch");
    ...
}
```

The order is deliberate. Cheap checks first. The length is checked against the real size **before**
anything allocates, so a damaged length field cannot ask for 2 GB. The checksum is verified before
the payload is parsed, so a flipped bit is caught as a checksum failure, not as a confusing value.

Then the payload is parsed inside a `try`. The parse can still fail, for example when the checksum
matches a damaged but self-consistent file. Everything that can go wrong in there is turned into the
one checked exception:

```java
} catch (IOException | IllegalArgumentException e) {
    // EOFException is an IOException: the payload ended early. IllegalArgumentException
    // is the Profile constructor refusing values that make no sense.
    throw new ProfileFormatException("payload: " + e);
}
```

`parse` also refuses extra bytes after the payload. A format that accepts trailing garbage is a
format that cannot tell when it has been written wrongly.

An older version has no new fields, so `parse` leaves `ourShots`, `ourHits` and the seed at their
defaults (0, 0, empty). That is `HL-19`.
