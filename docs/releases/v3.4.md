Hadur 3.4: memory that stays cheap at rumble scale. The three safe parts of R8
([docs/rumble-memory-scale-plan.md](https://github.com/lgriffin/Hadur_Robot/blob/master/docs/rumble-memory-scale-plan.md),
[docs/skipped-turns-plan.md](https://github.com/lgriffin/Hadur_Robot/blob/master/docs/skipped-turns-plan.md)),
on top of 3.3. Nothing in the fighting code changed.

**Download:** `hadur2.Hadur_3.4.jar`, attached to this release, at
`https://github.com/lgriffin/Hadur_Robot/releases/download/v3.4/hadur2.Hadur_3.4.jar`.
Robocode name `hadur2.Hadur 3.4`; runs on Java 11 or later. Enter it in both the RoboRumble
(1v1) and the MeleeRumble in place of 3.3: see
[docs/rumble-submission.md](https://github.com/lgriffin/Hadur_Robot/blob/master/docs/rumble-submission.md).

## Why

A rumble client keeps Hadur's data directory for hundreds of battles, one file per
opponent. 3.3's saves listed and, near the quota, read every file in it, so a save grew
with the directory and stalled the robot for a hundred or more turns at each round end.
Once the directory reached the 200 KB quota, saves were skipped and Hadur stopped learning
about new opponents.

## What changed

- **MEM-11:** the data directory is listed once per battle; every later size and name
  question is answered from an index the store keeps current.
- **MEM-12:** only files over 1 KB (the only ones that can hold seeds) are read to find
  seed holders.
- **MEM-13:** when a save would not fit, the least recently fought opponents' profiles are
  deleted, whole, until it does. Saves are no longer skipped on a full directory.

TIME-6 (answer the first turn before the battle's set-up) was built and benched, and
dropped: it moved the set-up out of the round start's long grace and cost 36 skipped turns
at the start of round 0. MEM-14, TIME-7 and RES-11 are left for later.

## Bench

`--client`, 4 weak bots, 10 rounds, CPU constant forced to 1 ms (a slow rumble client),
data directory prefilled with 700 profiles (199.6 KB of the 200 KB quota):

| | Skipped turns a battle | Of which after the round was decided | Survival |
|---|---|---|---|
| 3.3 | 188 to 224 | 772 of 814 | 90 to 100% |
| 3.4 | 10 to 26 | 43 of 67 | 100% |
| 3.4, empty directory | 8 to 18 | | 100% |

Weak set (`weak-pbi.txt`, 35 rounds, shared data directory): all 12 bots 35 of 35, 0 to 4 skipped turns a battle; details in
[docs/bench/r8-memory-scale.md](https://github.com/lgriffin/Hadur_Robot/blob/master/docs/bench/r8-memory-scale.md).
